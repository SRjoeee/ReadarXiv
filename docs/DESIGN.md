# Read arXiv — Design

The current design of the extension: what it does, how it is built, and why each choice that is not obvious was made. Cite it by section (`DESIGN §7.2`); a decision that changes goes into its section, in the pull request that changes the code. What the extension does for a reader is in the README; how a version is cut is in `RELEASE.md`.

Where this document and the code disagree, one of them is wrong; the same pull request settles which. A decision — structural or not — changes here, in its section, in the pull request that changes the code; the measurements that justified it stay beside it.

---

## 1. Goals and scope

**What it does.** A Chrome extension (Manifest V3, Chrome 131 and later) for arXiv's HTML papers, `https://arxiv.org/html/*`. It translates the paper in place, beside or under the original, so that formulas, citations, links, tables and figures keep working and the reader can check any sentence against the original without leaving the page. Restoring the original is lossless. Made for long reading sessions.

**In scope.**

- Chrome only; arXiv HTML only. The extractor is written as a site adapter for LaTeXML output (§5); no second site is planned before the first is finished.
- Three reading modes — side by side, stacked, translation only (§7) — switchable at any time, with a lossless restore.
- Translation services: the services the reader adds (OpenAI-compatible endpoints: OpenRouter, DeepSeek, a local Ollama, and so on), and three free engines — Microsoft's web translator (the default on first install), Google's web translator, and Chrome's built-in translator — on an automatic fallback chain (§8.5).
- A local cache: a paper reopened shows its translation at once (§9).
- The reader's own translation appearance, prompts and glossary (§7.5, §8.2).
- Sentence highlight on hover, and in translation-only mode the original sentence floating beside the translation (§7.7).
- Figure translation: the labels inside bitmaps (through a local macOS helper that runs Apple Vision) and inside externally referenced SVG figures (read from the glyphs, no recognition needed), overlaid in place; and the labels of inline TikZ pictures, which are HTML in the page and are translated as text, each in its node, in the figure's own face and colour (§15).
- The bilingual entry on the abstract page, a keyboard shortcut and a context menu item (§4.0b); an interface in English and Chinese; a diagnostics log a reader can attach to an issue (§4.6).

**Not in scope for this release**, on purpose: a reader outside the extension (a web page or an app translating the same papers — the platform boundary of §4.2 keeps the core free of the extension's APIs so that one can be built on it, and that is all this release does about it), other paper sites, PDF, bitmap recognition off macOS (a hosted recogniser plugs into the recognition seam (§15.3) when one is built), other free engines (DeepLX, Edge), a configurable order of the free engines (issue #103, no benefit found), a published `@readarxiv/core` package, Firefox or Safari.

## 2. Core judgements

arXiv's HTML is generated by LaTeXML: the DOM is regular and every element carries an `ltx_*` class. Everything below follows from taking that seriously.

1. **Deterministic rules, not a heuristic walker.** A general-purpose translator has to guess which nodes are text and which are chrome; here a table of rules aimed at LaTeXML decides what is a block, what is skipped and what is protected. The rules live in one file and carry a version (§5).
2. **One DOM, three modes, one attribute.** A translation is inserted as the next sibling of its original block and never changes the original's subtree; a mode switch changes one attribute on `<html>`. Reversibility rests on this (§7.1).
3. **The wire format is negotiated from what the engines preserve, not chosen by engine type.** `tags` sends the whole block with tag placeholders, `markers` with plain-text markers, `runs` cuts the block into segments at the protected nodes. A provider declares the formats it keeps (`wireFormats`, ordered by preference); the chain settles on one for the session (§8.5); the renderer never asks which engine produced a translation.
4. **Requests run in the background.** The engines, their queues, the fallback chain and the cache live in the service worker; the content script extracts, schedules and renders, and its only traffic is messages (§8.0). The reasons are measured: a content-side request carries the page's origin, is bound by CORS, and cannot reach a local endpoint at all.
5. **What the engine cannot tell us is not guessed.** Sentence pairs come from the engine's own boundaries or from markers the service inserted, never from matching two finished texts by position; an alignment that does not reconstruct both texts is dropped, and a dropped alignment costs only the highlight (§8.6).
6. **Translate what is seen.** Only the blocks in and near the viewport are requested; nothing beyond the preload distance costs a request (§10).

## 3. Terms

| Term | Meaning |
|---|---|
| Block | One translation unit — one LaTeXML element such as `.ltx_p`, `.ltx_title`, `.ltx_caption`, or the whole outermost `.ltx_tabular` |
| Protected node | An inline node inside a block that is not translated and must come back as it is: a formula, a citation, a cross-reference, code, a footnote mark |
| Placeholder | What stands in for a protected node in the text sent to the engine: in the `tags` format void `<x id="n"/>` and paired `<t id="n">…</t>`, in the `markers` format void `@a#` only |
| Wire format | The placeholder syntax of a request: `tags` or `markers`. A provider declares the formats it preserves (`wireFormats`); a session uses exactly one |
| Render path | `tags`, `markers` or `runs` — the wire format the block was sent in, or `runs` when it was cut into plain-text segments. Enters the cache key |
| Mode | `side`, `stack` or `only`, carried by `html[data-axt-mode]` |
| Provider | One translation engine behind the common interface (§8): a built-in free engine or a service the reader added |
| Chain | The providers a session may use, in order: the chosen one first, then the free engines that can serve as fallbacks (§8.5) |
| Surface | One of the extension's own pages that shows and changes the settings — the popup, the settings page. Each reads, patches and follows the one stored configuration through the surface configuration (`shared/surface-config.ts`, §9). Not the arXiv page, which is "the page" |
| Session | One translation of one page: from the start command to restore, tab close or navigation (§4.3). It has an id, which is also the **scope** every request and recognition carries, so that everything queued for a page that ended can be withdrawn (§8.0, §8.5) |
| Run | The state machine that takes a session's blocks (the text run) or images (the image run) through requested → done or failed, on one ledger (§4.4) |
| Helper | `axt-helper`, the local macOS program that recognises text in bitmaps, reached over Native Messaging (§15.4) |
| Fixture | A real arXiv HTML page kept under `tests/fixtures/arxiv/` for the tests |

**Names**. The internal name is `readarxiv`; the display name is **Read arXiv**; the repository is `SRjoeee/ReadarXiv`. Everything the extension writes is prefixed: classes `axt-`, attributes `data-axt-`, CSS variables `--axt-`, messages `axt:`, storage keys and the helper binary likewise. Four older names stay by contract and are not to be "fixed": the Native Messaging host `io.github.srjoeee.arxivtranslate`, the helper's install directory `~/Library/Application Support/Readarxiv/helper`, the `axt-` prefix itself, and the prompts export file `arxiv-translate_prompts.json`.

## 4. Overall architecture

```
content script — arxiv.org/html/*                                  background — the service worker
─────────────────────────────────────────                          ────────────────────────────────────────────
rules → extractor → session ─┬─ text run:  scheduler → protector ──┼─► axt:translate → chain → queues → provider → cache
                              │            ← rehydrate ← renderer ─┼─◄ the translated segments (+ alignment)
                              └─ image run: fetch/hash, SVG glyphs ─┼─► axt:ocr → OCR cache → helper (Native Messaging)
                                           → boxes → axt:translate  │
                                                                    │   sessions router · provider status · engine-ready
                                                                    │   diagnostics ring · helper install waiter
pages: popup · options · gallery (dev)     abstract-page script     │   context menu · keyboard command · alarms
```

**Where things live.**

| Directory | Holds |
|---|---|
| `src/core/rules` | The one file of `ltx_*` selectors and the classification (§5.6) |
| `src/core/extractor` | Blocks out of a document, marks, statistics (§4.1) |
| `src/core/protector` | Serialisation to placeholders, validation, rehydration, the runs path (§6) |
| `src/core/renderer` | Insertion, the three modes, side-mode tidying, restore, the hover highlight (§7) |
| `src/core/scheduler` | The viewport observer, the title, session ids (§10) |
| `src/core/pipeline` | The text run: batching, sentence cuts, the fallback to runs (§10, §8.6) |
| `src/core/image`, `src/core/svg` | The image run and the SVG glyph reader (§15) |
| `src/core/viewer` | The figure viewer: a figure opened large, zoomed and panned (§15.7) |
| `src/core/sentences` | The sentence splitter (§8.6) |
| `src/core/run`, `src/core/session` | The ledger both runs share; the page session (§4.3, §4.4) |
| `src/core/abstract` | The bilingual link on the abstract page (§4.0b) |
| `src/providers` | The engines, the queues (`request/`), the translate service, the fallback chain, prompts, glossary, alignment (§8) |
| `src/cache` | The Dexie store and the cache key (§9) |
| `src/config` | The schema, versions and migrations, languages, appearance, services (§9) |
| `src/entrypoints` | `background/`, `content/`, `popup/`, `options/`, `gallery/` (a dev page of UI states), the abstract-page script |
| `src/shared` | The message table, the two transports' shared shapes, OCR shapes, diagnostics shape, hashing |
| `src/ui`, `src/locales`, `src/styles` | React components, the locale packs, the injected style sheets |
| `helper/` | The Swift package of `axt-helper`, its installer and registration scripts (§15.4) |

**Data flow for one block.**

1. `extract(doc)` collects every block by the rules and, when translation starts, `markBlocks` writes each one's stable id (`data-axt-id`). Nothing is written before a translation starts: a mode chosen on an untranslated page is a saved preference and no more — no attribute, no controller left listening — and the start that follows reads it. Mode saves run in order, and a mode saved in another tab becomes the untranslated page's preference too.
2. The scheduler hands over blocks as they enter the viewport plus the preload distance (§10); the ones never scrolled to cost nothing.
3. The protector serialises each block into `{ format, text, slots }` in the session's wire format (§6.2); the pipeline chooses the sentence cuts (§8.6) and batches by section (§8.2).
4. `axt:translate` carries the batch to the background. The translate service looks the segments up in the cache, sends the misses through the provider's queues (rate, concurrency, batching, retries; §8.2–§8.3), verifies the placeholders and the alignment, and writes what passed into the cache (§9). On a failure the fallback chain hands the same call to the next engine (§8.5).
5. Back in the page, the pipeline re-checks that the block is still what was serialised (§6.4), rehydrates the placeholders into clones of the protected nodes, and the renderer inserts the translation as the block's next sibling (§7.1). A block that fails gets a widget with the reason and a retry (§7.6).
6. Mode switches and restore touch none of the above: a mode is one attribute on `<html>`; restore deletes what was inserted and strips what was marked.

### 4.0b Seven entry points

Translation starts only on the reader's action, and every road lands on the same pair of page commands, `axt:translate-page` / `axt:restore-page` — one implementation, seven doors:

- **The popup**: translate / restore, mode, service, language, prompt, progress; the most complete one. **It works on the abstract and PDF pages too** (UI.md S-P-03b): those content scripts answer `axt:entry-status` with the paper and where its HTML version is, and the button then sends `axt:open-html`, which the page follows itself — no `tabs` permission is involved. A paper with no HTML version leaves the button disabled with the reason, rather than the popup's "not an arXiv page" screen.
- **The keyboard command** `axt-toggle` (suggested Alt+T): the same toggle as the context menu. The popup shows the key as Chrome reports it (`commands.getAll()`), so a rebound or removed shortcut is never advertised wrongly.
- **The context menu**: one item, translate or show the original, limited to `https://arxiv.org/html/*`. It asks `axt:page-status` before deciding which command to send; its label does not follow the page, since `contextMenus.update` is global and would be wrong the moment the tab changes.
- **`#readarxiv` in the URL**: the content script starts translating on entering the page. A debugging hook that became a product interface — and, staying in the address bar and travelling with a link a reader passes on, one that carries the product's name rather than the code's prefix (the maintainer, 2026-09-19). It was `#axt-translate` through 0.4.0, which still starts the translation: a bookmark or a shared link made then is somebody's saved way in (`startsTranslation`, any capitalisation). Its sibling stayed a developer's tool and is no door: `#axt-debug` marks the extracted blocks and outlines them — text blocks red, tables blue — to see what the rules make of a page (`content/debug.ts`); the style is its own, injected only then, and a restore or a reload without the hash leaves nothing.
- **The abstract page**: a separate content script on `arxiv.org/abs/*` inserts one line after arXiv's own HTML link, pointing at **the href arXiv gives** plus `#readarxiv`. The href is arXiv's, never built by hand — it carries the paper's version; a paper without an HTML version gets nothing inserted. This script loads none of the translation pipeline.
- **The PDF page** (issue #169): a content script on `arxiv.org/pdf/*` offers the HTML full text plus `#readarxiv`. Chrome puts a PDF into a synthetic host document at the paper's own URL, and a content script matching that URL runs in it; the viewer is a separate `chrome-extension://` frame and is untouched, while a `position: fixed` element in the host document draws above it (measured 2026-09-18, Chromium 153). Whether an HTML version exists is one `HEAD` on `arxiv.org/html/<id>` — **same-origin, so no host permission is involved** (measured: 200 for a paper with one, 404 for a paper without). The id comes from the path, with the version the reader opened. What is shown there is the floating button (§4.0c), its main button a link carrying the same sentence as the abstract page's entry (UI.md S-I-06); without an HTML version the button stays and its main button is disabled, saying why, as the popup does. This script loads none of the translation pipeline either.
- **The floating button** (§4.0c), on the abstract page, the PDF and the full text alike. On the full text its main button is a fourth road to the toggle the key and the menu share: the page sends `axt:toggle`, the background decides (`shared/page-action.ts`) and tells the tab, so the doors cannot disagree. When nothing can be done — no service can run — the page opens its control panel, which is where the reason is said, rather than meeting a click with silence.


**Where the translation opens** (`reading.openIn`, configuration v16): a new tab by default, so the abstract page or the PDF the reader came from stays open behind it; “this tab” is the other choice, on the settings page. The two in-page entries are links, and carry `target="_blank" rel="noopener"` accordingly; the popup's button opens the tab itself (`tabs.create`, no permission) or asks the page to navigate. The first version navigated the tab and took the reader's page away, which is the defect this setting answers (the owner, 2026-09-18).

### 4.0c The floating button

One button on every arXiv page the extension knows — abstract, PDF, full text (the maintainer, 2026-09-18: it is there on all three) — docked to the window's edge: **the control panel** above (the extension's popup, framed in the page beside the button), **our mark in a circle** in the middle (translate this page or show the original on the full text; a link to the bilingual version on the other two; disabled with the reason where the paper has no HTML version), **the settings** below. Beside the main button, once open, a close control (hide for now · don't show again) and a lock. `core/floating/button.ts` draws it, `shared/floating.ts` gives it its life on a page, and the three content scripts differ only in what the main button does. Inside its shadow root every class, data attribute and CSS variable carries the prefix as everywhere (`axt-fb-…`, `data-axt-…`, `--axt-…`): a shadow root needs no protection from the page's names, but one rule without an exception is worth more than shorter names, and a test holds it.

**The frame is Read Frog's** (ported 2026-09-18 at the maintainer's request, GPL-3.0, `docs/THIRD_PARTY.md`): the column around a main button, the corner controls, the tooltips on the side away from the edge, the surfaces and sizes, and the whole drag — a long press (350 ms) or a movement past 6 px starts it, the button follows the pointer as a circle, the release docks it to the nearer half of the window, and its height is kept as a fraction of the window, held 30 px from the top and 200 px from the bottom; fullscreen cancels a drag under way. Plain DOM in a shadow root, not their React component: that needs React, jotai, Tailwind and Base UI, four dependencies for one button on every page opened (the reason §7.6 gives for the failure widget).

**How it rests and opens follows Immersive Translate**, which the maintainer asked to be studied; measured on its 1.33.1 in Chromium 153 (none of its code is used):

| | Immersive Translate, measured | Here |
|---|---|---|
| At rest | a 41 × 36 tab flush with the edge, the whole 28 px circle showing, opacity 0.7 | a 44 × 40 tab (Read Frog's size), the whole 32 px disc, opacity 0.7 |
| Pointer arrives | opacity to 1 over 250 ms ease-out, at once | the same, and the disc's shadow deepens |
| The other buttons | appear about 500 ms after the pointer arrived, fading in over 110 ms | 400 ms — right after the light-up ends, so the two read as one motion — fading in over 110 ms with an 8 px slide |
| Pointer leaves | about 200 ms of grace, then the buttons fade (110 ms) and the circle dims (250 ms) | the same |
| A translated page | an 11 px green tick at the circle's lower right | a 13 px green tick at the circle's lower right, and the main button's words become “show the original” |
| Drag | both axes, docks to the nearer side, keeps its height | Read Frog's, which is the same and adds the clearances and the lock |

Read Frog's own resting state — pushed 24 px out of view at 60 % — is what this replaces: a mark half out of the window does not say what it is.

**The mark is the maintainer's: our book in a white disc** (exported 2026-09-18; the book spans 70 % of the circle), inline vector in `core/floating/mark.ts`. The first version put `mark.svg` in an `<img>` 22 × 18.08 px behind a 1.5 px crimson border, and looked at closely it was soft: the image was resampled at a fractional size, the border broke into dashes on a 1× screen, and the whole button sat on a fractional pixel because its place was `66vh` (measured: top 609.59 px). Now the mark is drawn as vector at the screen's resolution, the disc's soft shadow is the style sheet's (the export's drop-shadow filter is left out: a filter rasterises the book with the circle), every length inside is a whole pixel, and the button's place down the edge is rounded to a device pixel. **The disc sits in the white tab as it was exported**, its edge said by the soft shadow alone (the maintainer's choice, 2026-09-18, after comparing four treatments switchable on live pages: as exported, a neutral hairline, a grey tab with the disc as a knob, no tab at all). The other three are kept, switchable as they were compared, on the branch `archive/floating-mark-variants` — a UI archive for later discussion, never merged.

**One size on every page** (the maintainer, same day: the button was larger on the full text than on a PDF). A reader's browser zoom scales a page and everything in it, but never the document that hosts Chrome's PDF viewer, which takes the tab's zoom for the paper (measured at a tab zoom of 1.5: `devicePixelRatio` 3 on the full text and still 2 on the PDF; the button 132 device pixels against 88). Following the zoom on the PDF was the other way to agree, and a worse one: there the tab's zoom is the paper's magnification, which "fit to width" changes by itself. So the button **undoes the page's zoom** and is the size of the toolbar's buttons everywhere, which zoom does not change either: the background answers a tab's zoom with the rest of a page's settings (`axt:entry-settings`, `tabs.getZoom` — no permission) and tells it of changes (`tabs.onZoomChange` → `axt:zoom-changed`), and the column and the panel carry CSS `zoom: 1 / pageZoom`. The dock that places them and the two full-window layers stay in the page's own pixels. It is also what keeps a zoomed page sharp: at 125 % the pixel ratio is 2.5 and nothing of the page's lands on a whole pixel, while the un-zoomed button is 88 × 80 device pixels again. The framed popup follows (measured on a real 2× screen: 640 device pixels wide and drawn at a ratio of 2 at every zoom). `tests/e2e/floating-button.mjs` holds both: the main button's four edges on whole device pixels, and the same device size at 100, 125 and 150 % as on the PDF.

**The icons are Lucide's** (ISC, `docs/THIRD_PARTY.md`): the first set was drawn by hand and the maintainer found it neither fine nor regular enough (2026-09-18) — a set drawn on one grid by people who do nothing else is both, and only the six glyphs used are bundled. Its licence ships in the package with every other bundled package's (`licenses/third-party.txt`, written by the build from what is in the bundle — `docs/THIRD_PARTY.md`), since the minifier drops comments.

**The control panel is a panel in the page, as Immersive Translate's is** (measured: a 316 px panel fixed beside its button, drawn in its own shadow root, a transparent layer over the window to close it on a click elsewhere). Ours frames the extension's own `popup.html` beside the dock — one popup, not a second copy of it in the content script, and none of React in the pages' scripts. The frame exists only while the panel is open (a popup polls its page while it is up); the page inside tells its owner its content's height and when it wants to go (`axt:panel-size`, `axt:panel-close` by `postMessage`, believed only when the message's source is that frame — `popup/embedded.ts`); the panel shows itself once it knows its height, centred on the main button and kept 16 px inside the window; a press elsewhere, Escape or a second click closes it, and on a PDF the layer behind the lit button is what hears that press. The first version asked the background for the toolbar's popup (`action.openPopup`): it opened under test and not in the maintainer's Chrome, and it was not what the reference does. `popup.html` is therefore web-accessible **to arXiv only**; a page that may frame the popup could try to trick a click on it, and what a click can do there is what the reader does there anyway — the popup shows no key and no paper text. A click on the main button that nothing can serve opens this panel, where the reason is said.

**One motion for everything that comes out** (the maintainer, same day: the parts came out on different curves, and flickered). The first version had the two side buttons fading in 110 ms and sliding in 160 ms, the two corner controls appearing at once on top of the main button and sliding out from under it for 300 ms, and the main button's tooltip jumping 20 px when the dock opened. Now the panel button, the settings, the two corner controls and the main button's tooltip enter together — one fade (200 ms) and one decelerating growth (280 ms) for all of them, each growing a few pixels out of the main button — and leave together in 140 ms. Only opacity and transform move, and the open state's layout is the closed state's (the room for the corner controls, the bridged gaps and the tooltip's place are always there), so opening lays nothing out again. `tests/e2e/floating-button.mjs` holds it by number: every part has the same opacity in every frame, no opacity falls back on the way in, and neither the main button nor the dock moves.

**The tick follows the page, not the click**: the session tells its state once per change (`SessionDeps.onState`, `core/session`), whoever asked — the popup, the key, the menu, the hash or this button. `on` shows the tick; `stopped` (a fatal error) does not, and the main button then retries, as the popup's does.

**The button's state is not in the configuration, and has one writer** (storage key `floatingEntry`: `enabled`, `side`, `position`, `locked`; `background/floating-entry.ts`). It was, for a day: configuration v17, written by the background as `getConfig()` → `setConfig({ …config, floatingEntry })`. That is a read-modify-write of the whole configuration from one more context, fired by a drag in any arXiv tab at any moment, and a whole-object write can put back a snapshot taken before another context's save — a service or a key just added on the settings page, gone (Devin on #250). The popup and the settings page serialise their own writes, each within its own context; nothing serialises across contexts, and `storage` offers no compare-and-swap. So the state left the configuration before any release (v18 drops the field; a test build's placement is not carried over): under its own key a drag can touch nothing but itself, the background is its only writer — the settings page's switch and the pages' drags all send `axt:set-floating-entry`, a patch — and the writes run one after another, each merged into what is stored at that moment. The answer carries the state that is stored now, and that is what the page shows: a change that could not be saved does not look saved.

**The pages ask the background for their settings; they read no stored value** (`axt:entry-settings`, `shared/entry-settings.ts`): the interface language, where a translation opens, the tab's zoom, the button's state. The first version read the raw stored configuration field by field, to keep the schema out of the abstract and PDF scripts. But a stored configuration this build cannot read is, everywhere else, replaced whole by the defaults and said to be so (§9), and a page picking fields out of it followed a configuration the rest of the extension had set aside — a newer build's `enabled: false`, a damaged `openIn` (Devin on #248 and #251). One validated reading, in the background; the scripts still load no schema, and ask again when either storage key changes. The abstract page's own link follows the same answer. Answers may come back out of order, and only the newest ask's is believed; a zoom the background pushes while an ask is out makes that answer stale **in its zoom alone** — the rest is taken. (Dropping the whole answer for a push lost the saved place on a PDF, whose viewer sets the tab's zoom as it loads, inside the page's first ask: three runs of five of `tests/e2e/floating-button.mjs` on 2026-09-19 found the button back at its default after a reload, and it would have shown for a reader who had turned it off.)

**Only arXiv saying so means a paper has no HTML version.** The PDF page's `HEAD` answers 404 for a paper without one; a request that failed, a 429 or a 5xx say nothing about the paper, and the button's "arXiv has no HTML version" would then be a false statement the reader keeps until a reload (Devin on #247). Unknown, the link is offered: at worst it leads to arXiv's own answer.

**A press covers the window with a transparent shield.** On a PDF the page under the button is Chrome's viewer, another process's frame, and the moves and the release of a press went there rather than to the captured button (measured: pointer capture granted, then not one `pointermove` or `pointerup`). With the shield, what lies under the pointer is this document's until the press ends; `tests/e2e/floating-button.mjs` drags it across a real PDF. **Leaving has the same trouble**: once the pointer is over the viewer this document hears no `mouseleave` and `:hover` on the button stays true (measured the same day, three ways of leaving), so an opened button would never fold and its menu never close. On a PDF document only (`contentType`), a second transparent layer lies behind the lit button and is where the pointer goes when it leaves; it is gone again the moment the button has folded. An ordinary page has neither problem and gets no such layer.

**Only what is drawn takes the pointer.** The column's box is mostly empty while folded, and `pointer-events: none` on it leaves the page its clicks above and below the tab (Immersive Translate's container does the same); open, the anchor reaches across the two 8 px gaps, so a pointer crawling from the main button to the panel never leaves the dock on the way.

**The hit area grows when the button lights — Read Frog's cure for a pointer at rest on the edge.** A hand at rest trembles a pixel either way, and an edge under it is crossed many times a second. Read Frog debounces nothing; its hover state is called `isHitAreaExpanded`, and means it: the boundary that opens is the main button's edge, the boundary that lets go is 24 px further out, so the resting pointer is well inside. Ours had that only once open, and opens after a dwell (Immersive Translate's manner), so for those 400 ms the edge was still an edge: the dwell was spent crossing it, and once open the main button's tooltip — which Read Frog's main button does not have, ours following Immersive Translate's — strobed against the two corner controls along that same edge (the maintainer saw it; measured: 48 reversals of its opacity in 1.5 s, the button itself never moving). Now the area — 24 px towards the page, 8 px above and below — is there from the light-up, and a tooltip that is up stays up for 120 ms after the pointer has left its button while the dock is open, the close delay tooltip libraries offer for this reason; hover feedback on the small controls goes after a beat likewise. A patch of timers that kept the dwell alive through the leave grace was written first and removed for this: geometry removes the cause, the timers filtered its symptoms. `tests/e2e/floating-button.mjs` trembles a real pointer on the edge: the dock opens, and no part's opacity reverses.

**On the full text the host is the one node of ours outside a translation** (§7.1): mounted after extraction, left alone by restore, and nothing else is written to the page until the reader asks.

### 4.1 Block model

```ts
type Block = TextBlock | TableBlock
interface TextBlock  { id: string; kind: 'text';  el: Element; unit: string }           // unit: the rule that matched (§5.1)
interface TableBlock { id: string; kind: 'table'; el: Element; unit: 'table'; cells: { el: Element; numeric: boolean }[] }
// id → data-axt-id: the element's own id when LaTeXML gave it one (S3.p1.1, stable across loads), else axt-b<n> in document order
// el: the original node, whose subtree is never modified; cells: every .ltx_td at any depth inside the outermost .ltx_tabular
```

- `extract(doc)` is read-only. `markBlocks(blocks)` is the one write, made when translation starts; the popup's block statistics come from the `Block[]` in memory, not from the DOM.
- **Traversal and classification are separate.** A pre-order walk from the translation root asks `classify(el)` and decides "emit" and "descend" apart: `skip` neither emits nor descends; `table` emits one block and does not descend (an `.ltx_p` inside a cell belongs to its cell); `unit` emits a block when the element has translatable text of its own and keeps descending for nested units; `protect` emits nothing and does not descend unless the rule says `descend: true` — a footnote (`.ltx_note`) is a void to its paragraph while the `.ltx_note_content` inside it is a block of its own, and an equation group is a void to its unit while its `\intertext` rows are blocks (§5.2).
- **Translatable text** is the text left after removing the protected and skipped subtrees, and it must contain a letter (`\p{L}`). A paragraph of formulas and numbering is no block; a table with no cell that is non-numeric and holds a letter is no block either.
- **Whether an enclosing unit really became a block is known only to the walk** (the `emitted` table): a unit that yields to its enclosing block (`YIELDS_TO_OUTER_BLOCK`, today the intertext rows) is emitted only when no ancestor unit emitted a block that already clones it whole — a selector match on an ancestor is not enough, since an `.ltx_item` holding only a nested paragraph and a formula is no block at all.

### 4.2 The platform boundary

`src/core/**`, `src/providers/**` and `src/cache/**` import nothing from `wxt`, `src/entrypoints`, `src/ui`, `src/locales`, `src/config/storage`, `src/shared/messages` or `src/shared/transport`; type-only imports are allowed. `scripts/check-boundary.mjs` enforces it on every `pnpm lint`, resolving every specifier to the module it names before judging, so a forbidden module cannot return under another spelling. What the core needs from the host enters as a dependency: the session takes its transport, OCR call, helper probe, configuration accessors, locale hook and trace sink; a provider takes `fetch`; the cache takes a database. What the core shows a reader is a code the host turns into a sentence (`StartRefusal`, `ProviderErrorKind`, `FallbackReason`), or one of the few strings a host installs through `core/strings.ts` (the failure widget's button and sentence, with an English fallback). No package is extracted: the check is the whole cost of keeping the option.

### 4.3 The page session

`createPageSession(deps)` (`src/core/session/index.ts`) owns one page's translation: its text and image runs, the title translation, the hover highlight, the mode controller, side-mode tidying, progress, the restart guard, and the reaction to configuration changes. It exposes `ready`, `start`, `restore`, `setMode`, `translate` (a retry of given blocks), `translateImages`, `retryFailed` (every failed block and image of the page, the popup's one button), `resumeRaster`, `onConfig` and `status`. Each `start()` captures its own id (`newSessionId()`) and closes over one `alive()`; there is no other way to ask whether a session is still current, and every write after an `await` asks it first. What a start creates — the id, the inputs it ran on, the mode controller, the anchor fallback, the hover highlight, both runs and the title translation — is one record (`LiveSession`), built in one place and ended as one (`endLive()`): `alive()` is "the record this callback closed over is the one in force", a restart or a restore ends the record and adds only what is its own, and the record stays after a fatal error stopped its run, since the translations are still on the page and the mode still switches. Image translation can be switched within a session, so its round is a record of its own inside the session's, replaced whole: a callback of a replaced round — a helper probe answering late — acts on nothing. The content entry (`src/entrypoints/content/index.ts`) is an adapter: it extracts the blocks, builds the session with the browser's real dependencies, and maps `axt:*` messages, `watchConfig` and the URL hash onto session calls; it holds no session state. One permanent-error policy is shared by the chain, the service, both runs and the session: `PERMANENT_ERROR_KINDS` is `no-key` and `auth` — the kinds that continuing can only repeat.

### 4.4 One ledger for both runs

`createRunLedger(targets, deps)` (`src/core/run/ledger.ts`) keeps what the text run and the image run used to keep twice: the outcome of every target (`waiting` / `requested` / `done` / `failed`) and its failure reason, the permanent-error record, the stopped flag, the lazy scheduler, and the questions asked of them — `halted()`, `progress()`, `failed()`, `inState()`. Work enters through `intake(picked)`: known, not-yet-requested targets are claimed from the scheduler and returned as `taken`, the rest as `held` (the image run parks them behind its mode gate). Policy stays in the runs: a permanent error makes the text run stop taking new batches while the ones in flight finish, and makes the image run fail every requested target and drain its pool. Both runs report busy → idle through one detector (`core/session/idle-trace.ts`), each with its own line, which the e2e suites parse. **The two run modules stay one file each** (`pipeline/run.ts`, `image/run.ts`; about 260 and 300 lines of code): what made them hard to follow was the state machine each kept for itself, and that is the ledger's now. What is left in a run is one closure over one session's state — send, the runs fallback, the single-block retry, a batch — and every part of it reads that state; split across files it would be the same state handed round as arguments. Size alone is no reason to cut it (the maintainer, 2026-09-17). What the runs do share beyond the ledger is the **envelope** a request goes out in (`core/run/call.ts`, `translateCall`): the text run's batches, the image labels and the tab title are one session's requests, and the part that must not differ between them is the context, which enters the prompt and the cache key (§9) — there an absent context and an empty one do not serialise alike, so an empty one is left out, in one place. The rest that looks alike in the two runs stays where it is: the three-line report guard, and the question whether a failure is permanent, whose consequences differ per run.

### 4.5 The message protocol

`src/shared/messages.ts` is the one table; popup, content and background may use no other shape. The groups:

- **Page commands**, background or popup → content: `axt:translate-page` (with `restart` to replace a running session in place), `axt:restore-page`, `axt:set-mode`, `axt:retry-failed`, `axt:page-status`. A command carries the page's action epoch, so a stale command from a popup that saw an older state is refused.
- **Translation traffic**, content → background: `axt:translate` (one batch, with the session scope and the cuts), `axt:cancel-scope`, `axt:provider-status`; `axt:engine-ready` from the popup or settings page after a language-pack download rebuilds the chain.
- **Images**: `axt:ocr`, `axt:helper-status`, `axt:helper-await` (start or query the install wait), `axt:helper-ready` / `axt:helper-state` broadcasts to the open pages and surfaces.
- **Data**: `axt:cache-stats`, `axt:cache-clear`, `axt:diag` (a line for the diagnostics log), `axt:diag-export`.
- **Packs**: `axt:pack-changed` between the popup and the settings page, so a language-pack download started on one surface shows on the other.

**Every asynchronous reply settles.** A handler that returns `true` and never answers leaves its sender waiting for as long as the worker lives, so each one answers through `replyWith`: the value, or a failure reply (`{ axtError, name }`) that the sending side — `sendMessage`, and `sendToTab`, the one place a tab is written to — turns back into a rejection carrying the error's `name`. The name is how a caller tells a failure it has a sentence for (a refused save, §9) from one it can only quote.

The background keeps a **session router** (`background/sessions.ts`): which tab holds which session scope, bound on the first request; a tab that closes or reports a different session drops its scope — queued and in-flight work is withdrawn on every service, and the scope is marked dead in the one `CancelledScopeRegistry` every service reads (§8.5): marked before anything is awaited, never expiring, so a call suspended on a cache read wakes to a scope already dead, and a chain built after the drop reads the same answer.

### 4.6 The diagnostics log

The background keeps a ring of the last 500 lines the extension logged (`background/diagnostics.ts`), mirrored into session storage so it outlives a recycled worker and ends when the browser closes; the content script forwards its `[axt]` trace lines through `axt:diag`, and request failures, hand-overs and withdrawals are recorded where they happen. The settings page exports it as a JSON file (`read-arxiv-diagnostics.json`) for a reader to attach to an issue. **What it never holds**: an API key (Bearer tokens, key query parameters and the common key shapes are redacted in `shared/diagnostics.ts`), page text, or any message text an endpoint returned — a failure line carries the kind, the HTTP status and the length of the withheld message, nothing else. The helper install command the settings page shows is stamped with the build's own commit (`scripts/build-ref.mjs`), so an installed helper matches the extension that asked for it.

## 5. Block model and rules

The rules live in `src/core/rules/latexml.ts` and nowhere else: no other TypeScript file writes an `ltx_*` selector (`tests/rules/selector-boundary.test.ts` scans for them); the style sheets under `src/styles/` may use them for layout only. Every arXiv page online today is generated by LaTeXML oxide 0.7.6 (§5.7).

**The translation root** is `article.ltx_document`. Everything outside it — the navigation bar and table of contents, the header and footer arXiv injects, the "report an issue" dialog, the announcement bar — is never extracted, and nothing has to be listed to keep it out.

### 5.1 Translation units

| Rule | Selector | Notes |
|---|---|---|
| `p` | `.ltx_p` | Body paragraphs, in the abstract, in list items, theorems and proofs alike — one rule, so that every text node falls under exactly one. May be a `<span>` (inside tables and inline blocks): extraction and rendering go by class, never by tag name |
| `title` | `.ltx_title` (not the acknowledgements' or keywords' own heading), `.ltx_subtitle` | Headings of every level. A section number inside (`.ltx_tag`) is a void; a theorem's run-in heading ("Theorem 1.") belongs here, and its environment name is translated (§5.2) |
| `caption` | `.ltx_caption` | Figure and table captions; the "Table 1: " tag is a placeholder whose name is translated |
| `footnote` | `.ltx_note_content` | The footnote body, a block of its own nested inside a paragraph: the paragraph sees the whole `.ltx_note` as a void, the extractor descends into it (`descend: true` on the protect rule), and the second mark and the "footnotemark:" label inside are voids |
| `bibblock`, `bibitem` | `.ltx_bibblock`; `.ltx_bibitem` when it holds no fragments | A bibliography entry is translated by its fragments (authors / title / venue, one line each), so a translation follows only its line (§5.4) |
| `ack`, `keywords` | `.ltx_acknowledgements`, `.ltx_keywords` | The container is the unit: its text is bare inside it, and its run-in heading is a paired placeholder translated with it — as a block of its own the heading would show twice in English above one Chinese paragraph |
| `personname` | `.ltx_personname` | Author names are translated (the owner's call, 2026-09-06): in the bilingual modes the original stands beside the translation; only mode hides the original for all content alike. Measured on 30 names with the worst free engine: 28 ordinary transliterations, Chinese names back as characters, one surname taken for a noun; the prompt was not changed for a 3% error rate |
| `authorinfo` | `.ltx_contact`, `.ltx_role_affiliation`, `.ltx_role_address`, `.ltx_dates`, `.ltx_date` | The author area is translated by default; only the conjunctions between names and the e-mail addresses stay out. An older policy that skipped the area whole missed author notes such as "Equal contribution" |
| `item` | `.ltx_item` | The bare text of a list item, and the term of a description list (`\item[Compactness]`, placed in the item's tag, §5.2) |
| `intertext` | the `\intertext` row of an equation group (`tr.ltx_eqn_row` without `.ltx_equation`) | Explanatory prose between aligned formulas: a cell spanning the whole row. The unit is the **row** — a cell's next sibling would be the next cell, and two `colspan`s would double the table's columns; the translation lands in a shallow clone of the cell, which carries the `colspan` and alignment. The row yields to an enclosing block that already clones the group whole (§4.1) |
| `dedicatory`, `marginal`, `indexentry`, `cv` | `.ltx_role_dedicatory`; `.ltx_marginpar`; `.ltx_indexentry`; `.ltx_cv_item_label`, `.ltx_cv_item_content`, `.ltx_cv_entry_date` | Structures that never occurred in a fetched paper, written from LaTeXML's conventions and guarded by `tests/fixtures/arxiv/synthetic-structures.html` (§5.7) |

Tables are not in this table: the whole outermost `.ltx_tabular` is one unit of kind `table` (§5.3), its cells segments inside it.

### 5.2 Skip rules and protected nodes

**Skipped** — the subtree is left out entirely; inside a unit it counts as a void:

| Rule | Selector | What it is |
|---|---|---|
| `equation` | `.ltx_equation` | Display formulas: single equations and the rows of a group. The group itself is not skipped, see below |
| `listing` | `.ltx_listing`, `.ltx_listingline`, `.ltx_listing_data`, `.ltx_verbatim`, `pre`, `code` | Code, verbatim, the hidden raw listing data; the lines inside an algorithm box, whose caption is translated as usual |
| `author-glue` | `.ltx_author_before`, `.ltx_author_after` | " and ", ", " between authors; as blocks they would break the name list |
| `classification` | `.ltx_classification` | MSC / ACM codes |
| `pubnotes` | `.ltx_pubnotes` | The ACM template's publication metadata |
| `picture` | `svg`, `.ltx_picture` | An inline TikZ picture: a **container** — one atom to an outer unit, entered for the labels inside (the `picturelabel` unit, `.ltx_foreignobject_content`; §15.6). Skipped whole until rules 0.11.0 |
| `error` | `.ltx_ERROR`, `.ltx_FATAL`, `.ltx_WARNING`, `.ltx_INFO` | LaTeXML's own notices, not paper content. A page that failed conversion (title "Untitled Document", one paragraph of errors) is handled quietly |
| `nav` | `.ltx_page_navbar`, `.ltx_TOC` | Outside the root anyway; listed so the renderer can name them |

**Protected** — a placeholder inside the enclosing block, put back as a clone on rehydration (§6):

| Rule | Selector | Notes |
|---|---|---|
| `math` | `math`, `.ltx_Math` | Inline formulas (display ones are skipped whole by `equation`) |
| `ref`, `cite` | `.ltx_ref` (with the `.ltx_ref_tag` inside), `.ltx_cite` | Cross-references and citations: 3 500-odd elements in the fixtures that would otherwise be paragraph text |
| `tag` | `.ltx_tag` | Numbers and markers — except the named tags below |
| `tt` | `.ltx_text.ltx_font_typewriter` | Monospace text, treated as code |
| `lstinline` | `.ltx_text.ltx_lstlisting` | An inline listing (`\lstinline`). LaTeXML sets it as a `ltx:text` **without** the typewriter class, its tokens in spans of their own (`ltx_lst_identifier`, `ltx_lst_keyword`, one `ltx_lst_space` per space), so until 0.10.2 it was walked as text and its identifiers went to the engine as prose — through the Edge endpoint `=` came back doubled, punctuation full-width, `let … in` translated. Measured over the 12 fixtures and 39 recent cs.PL / cs.SE papers (2026-09-19): 551 of them, all code (8 characters at the median, 56 at most; 30 hold a formula, which the clone keeps), not one protected by `tt` or inside a block listing. `.ltx_text` is the point of the selector: the class also sits on block listings (skipped whole already), on the **float that wraps a listing with its caption** — which must stay open — and on `mrow` / `mtext` inside formulas |
| `note` | `.ltx_note`, **descend** | The whole footnote is a void to its paragraph; the walk continues into it for the `footnote` unit |
| `equationgroup` | `.ltx_equationgroup` (table and span forms), **descend** | The group is one atom to its enclosing unit — narrowed to `table.`, a span-form group inside a list item would be serialised as a run of independent voids, and since an engine may reorder placeholders its rows could swap — while the walk continues into it for the intertext rows. Only the table form is rendered row by row and split in side mode |
| `note-mark` | `.ltx_note_mark`, `.ltx_note_type` | Footnote marks and the "footnotemark:" label |
| `mailto` | `a[href^="mailto:"]` | E-mail addresses |
| `contact-label` | `.ltx_contact_name` | "Affiliation: " / "Email: ", generated by the template and hidden by arXiv's style sheet; translated, an e-mail block whose only visible text was this label showed the address twice |
| `nodisplay` | `.ltx_nodisplay` | What LaTeXML marks as not displayed — the ACM `\Description{}` accessibility text, hidden by ar5iv: several hundred words per figure that a caption's translation once printed onto the page |
| `bib-year`, `indexrefs` | `.ltx_bib_year`, `.ltx_indexrefs` | A year in a reference, index cross-references — voids, since a paired placeholder's content still gets rewritten by an engine |
| `img`, `br` | `img`, `br` | Inline images and line breaks |

The hidden-element cases (`contact-label`, `nodisplay`) are rules, **not a general "skip whatever the computed style hides"**: measured, reading `display` / `visibility` once per element costs only 12 ms on the heaviest fixture, but it would catch nothing today (every hidden subtree with letters already falls under a rule) and it would make the extractor depend on layout and style sheets, whereas today it is pure DOM and 1 400-odd unit tests run the whole extraction in happy-dom for exactly that reason.

**Named tags are translated.** LaTeXML puts the names of theorem environments, figures, tables, algorithms, appendices and parts into `.ltx_tag` as well, so "Definition 1.1." used to stay English inside a translated heading. The subclasses `ltx_tag_theorem` / `figure` / `table` / `float` / `appendix` / `part` / `chapter` take part in translation (`NAMED_TAGS`), on a content check (`isNamedTag`): after removing the parenthesised parts that hold only identifiers, two or more letters must remain — `(a)` panel labels stay voids, `(Figure 1)` keeps its name — and **Roman-numbered tags are never translated**: an engine renders `Table IV:` as `表四：` while the `.ltx_ref` pointing at it is protected source text, so body and cross-references would stop matching; Arabic and letter numbering were measured to come back as they were. Measured on the fixtures' 1 241 tags: of 387 named tags 368 are translated and 19 protected. The terms of a description list (`.ltx_tag_item` with words: `Compactness.`, `RQ1`) go the same way; the 363 marker-like ones (`(1)`, `•`) stay voids.

### 5.3 Tables

The whole **outermost** `.ltx_tabular` is one unit (15 of the fixtures' 58 tabulars are inside no `.ltx_table`, so the root cannot be the figure; 3 are nested, and the inner one belongs to the outer cell; every `th` carries `ltx_td`, so `.ltx_td` is the cell selector; the cells of formula alignment tables are already skipped by `equation`).

- In side and stack mode a translated **clone** of the table is inserted after the original and filled cell by cell; numeric cells are copied as they are. In only mode the original is hidden and the clone shown. There is no comparison inside cells.
- **A cell is a segment inside the block, not a block**: the extractor does not descend into tables, and when the protector serialises a cell it walks into the `.ltx_p` and headings inside as ordinary paired nodes — as voids, the whole cell would be one placeholder and its text lost. Nested tabulars: their cells are cells of the outer block too; an outer cell holding only a nested table is copied as numeric. When filling the clone, each cell is located afresh before it is replaced: the outer cell's translation carries a clone of the inner table, so the outer cell is filled first and the inner ones after.
- **A partial failure counts as a failure**: the translated cells show, the block counts as failed, and the original stays `translated` with `data-axt-partial` for the hint — marking it `failed` outright would make only mode reveal the original beside the half-filled clone.
- **The numeric-cell test** looks at the visible text with protected and skipped subtrees removed (never `textContent`, which mixes in MathML's TeX source), calibrated on 5 487 real cells (§5.7): a cell is copied as it is when it matches `^(?=.*\d)[\s\d.,+\-±×^%()/*eE−–—:;~<>=≤≥∼]+(\s*[a-zA-Zμ°%]{1,4})?$` (a digit required, so `ERROR` is not an exponent), `^[✓✗✔✘–—−\-·×*]+$` or `^N/A$`. Empty and pure-formula cells are copied; upper-case enumeration values (`TRUE` / `FALSE`) go to the engine.
- A table block is one batch (§8.2), since the clone needs every cell together; `lang` and `dir` go on the cells whose content was replaced, never on the `<table>` (§7.1).

### 5.4 Bibliography

- Translated by default; there is no switch.
- **By the fragments inside an entry**: LaTeXML splits a reference into several `.ltx_bibblock` (authors / title / venue), and the unit is the fragment, so a translation follows only its line. An entry without fragments falls back to the whole `.ltx_bibitem`.
- **Every fragment, the author list included** (the owner's call, 2026-09-06): skipping "the first paragraph" by position skipped whole entries on templates whose first paragraph is the whole citation and second the DOI (12 of 13 references on one reported paper), while single-paragraph styles had their author names translated anyway. Cost measured over 12 fixtures: +5.7% blocks, +2.2% characters. A free engine transliterates a bare author list more readily than one mixed into a full entry (`Anthropic.` → 人类学。, initials' periods eaten); the LLM prompt keeps names, journals and identifiers in the original. **No rule is added for name quality**: a translated name is inexact by nature, and rules for it slide toward dictionaries and engine special cases. Traceability rests on the placeholders, not on the name: the year (`.ltx_bib_year`), the DOI / arXiv link and the cross-references are voids that an engine cannot rewrite, and a translation failing validation never enters the cache.
- In only mode the entry stays readable line by line; a DOI or URL is an `<a>` kept through its placeholder.

### 5.5 Rule versioning

- `RULES_VERSION` (`0.10.2` today) is exported by the rule file and is part of the cache key: a change that makes the same text translate differently must bump it.
- **When not to bump**: a purely additive change (a shape newly extracted, a group newly protected) may keep the version **only when the wire text of every block of every fixture is byte for byte unchanged** — then a changed block's key changes by itself through `normalizedText`, and no stale entry can be hit. A bump voids every reader's whole cache and costs LLM users real money; the criterion is measured, not argued (issue #152 kept `0.10.1` this way; protecting inline listings did not meet it — the wire text of 12 blocks of 2312.17141 changed — and moved it to `0.10.2`).
- The fixtures record their generator version. arXiv has reconverted its whole history with oxide 0.7.6, so no older output exists online and the year of a paper is no proxy for a version; should a future LaTeXML differ enough, the answer is a second rule file plus a detection function, not conditionals inside one.

### 5.6 Rule interface and precedence

`latexml.ts` exports data tables and pure functions only; the traversal is the extractor's (§4.1).

- Tables: `UNIT_RULES` (§5.1), `TABLE_RULES = { root: '.ltx_tabular', cell: '.ltx_td' }`, `SKIP_RULES` and `PROTECT_RULES` (§5.2, a protect rule may carry `descend`), `NAMED_TAGS`, `YIELDS_TO_OUTER_BLOCK`; the layout selectors the renderer composes (`SIDE_LAYOUT`, `FIGURE_SELECTORS`, `FIT_TARGETS`, `SPLIT_ROOTS`, `MARGIN_ASIDE`, `NOTE`, …) — LaTeXML knowledge as well, so they live here and the renderer only assembles them (§7.2).
- Functions: `documentRoot(doc)`, `classify(el) → { kind: 'skip' | 'table' | 'unit' | 'protect', rule } | null`, `isNamedTag(el)`, `isNumericCell(text)`, `visibleText(el)`, `proseText(el)`, `tableCells(table)`, `eqnProseCell(row)`.
- **Precedence**: an element matching several kinds takes `skip > table > unit > protect`.

### 5.7 How the rules were calibrated

The rules were not made complete by enumerating class names. `ltx_*` is an open set — `ltx_theorem_<name>`, `ltx_bib_<field>`, `ltx_citemacro_<macro>` are generated from the authors' own macros, and the union of every LaTeXML and arXiv style sheet (322 classes) misses 88 that real pages carry while listing 145 that never occur. Completeness comes from structure: containers need no rules, and text lands in a few units such as `.ltx_p`. The evidence, from the Phase 0 audit (2026-09-03 … 09-05) and kept as the working method:

- **Corpus**: 12 real papers under `tests/fixtures/arxiv/` (their reasons and licences in `tests/fixtures/README.md`) — formula-dense, code and algorithm boxes, large numeric tables, footnotes and theorems, one failed-conversion page; plus `synthetic-structures.html`, written after LaTeXML's output conventions for the 145 structures no fetched paper had (index entries, CV fields, dedications, margin notes, description terms) and later for shapes met in real papers but not in the fixtures (the `\intertext` row, copied byte for byte from a live page). A 13th real paper was measured to push the corpus tests over the vitest worker's heap — every paper keeps its whole DOM plus an `outerHTML` snapshot — so new shapes go into the synthetic file.
- **Coverage**: `pnpm fixtures:stats` classifies every non-blank text node under the root through `classify()`: **0 uncovered of 112 268** on the fixtures, and 1 of 36 348 over 20 further papers from eight subject areas (an MSC code, rightly skipped). The unit rules are pairwise exclusive, so "exactly one rule per text node" holds; adding a rule reruns the audit.
- **What the audit found and the rules absorbed**: cross-references, citations and footnote marks are protected nodes, not paragraph text; footnotes are nested blocks; the acknowledgements, keywords and subtitle are units; publication metadata, dates and pictures are skipped; the numeric-cell regex was calibrated on 5 487 cells (59% matched, 31% prose; `ERROR` and `✓` / `N/A` were its two classes of mistake).
- **arXiv facts that shape the rules**: every page is oxide 0.7.6, historical papers included (56 candidates from 2023 to 2026 checked); some papers have no HTML (404) and some failed conversions are published (`.ltx_ERROR`, one paragraph); old-style ids (`hep-th/9901001`) have HTML too, so `paperIdFromUrl` accepts `archive[.subject]/YYMMNNN[vN]`; the text outside the root is only the table of contents and arXiv's own chrome.

## 6. Placeholder engine

`src/core/protector/`. The one module written from scratch rather than ported, and the one that decides whether a translated paper still works: every formula, citation, link and footnote a block holds goes to the engine as a placeholder and must come back as it went. The completeness check follows Read Frog's `html-attribute-markers.ts`; everything else is ours.

### 6.1 Node classification

| Kind | Placeholder | Nodes |
|---|---|---|
| void | `<x id="n"/>` (tags) · `@a#` (markers) | Every protected node of §5.2: inline formulas, `.ltx_ref`, `.ltx_cite`, tags, code and typewriter text, the whole `.ltx_note`, footnote marks, `mailto` links, the hidden labels, inline images, `br`; a nested unit that became a block of its own; inside a unit, anything a skip rule matches |
| paired | `<t id="n">…</t>` (tags only) | An `a` with text, `.ltx_text.ltx_font_*`, `em`, `strong`, other spans holding translatable text |
| text | as it is | Text nodes |

### 6.2 Serialisation

```ts
interface ProtectedBlock {
  format: WireFormat            // 'tags' | 'markers'; validation, rehydration and cutting tokenise by it
  text: string                  // the wire text, text nodes escaped by format
  slots: Map<number, Node>      // id → the original node (the whole node for a void, the element for a paired one)
  paired: Set<number>           // which ids are paired (always empty under markers)
  voidCount: number             // beyond VOID_DENSE_THRESHOLD (40) the block is formula-dense and batches alone
  offsets: WireSpan[]           // wire offset → DOM position, one span per run of text; what the hover highlight reads (§7.7)
  spaced: Map<number, Sides>    // the markers that touched a word, and on which side: there the wire carries a space of ours (below)
  root: Element                 // the element that was serialised — the stale check re-serialises it (§6.4)
}
```

- Ids count up from 1 within a block. The `markers` format spells the id as bijective base-26 letters (1 → `a`, 27 → `aa`), because machine-translation engines reorder and merge digits.
- **`markers` has no paired placeholders**: measured on Google, paired markers survived only 70.6% of the time. Elements with a function (links) stay voids so that they stay clickable; every other paired element is flattened to text. What is lost is inline styling, not content.
- **A marker that touches a word is set apart from it by a space** (`markers` only). `@a#Word` reads to a machine translator as one token — a hashtag after a mention — and `word@a#` as an address, and neither is translated. Every numbered heading went out as `@a#Backpropagation recursion`, the section number's own space being inside the protected tag, and came back `@a#Backpropagation递归`, `衍生因子@a#Products`, `@a#Complexity` (the maintainer's report, 2026-09-19). Replayed through the Edge endpoint over the 404 blocks of the 12 fixtures with such a join — 9 % of all text blocks: 213 headings, the word before a footnote mark, a citation or a bibliography's year, an affiliation after its label, a caption after its tag, a line after a `<br>` — the touching word came back in English in **330 of 330** as sent and in 26 of 330 with the space (names and units, mostly), the markers intact in 400 and 401 of 404; Google, which takes markers as a fallback of Microsoft's chain, keeps `@a#Word` but leaves `this@b#` in English and loses the marker itself on `@b#th` (`第 b 个`), and keeps both with the space. The space is **the wire's, not the page's**: it maps to no character of the DOM (an anchor of its text run says so, so offsets on either side land on the text's own edge), `rehydrate` takes the space on that side of that marker off the translation (the target spans' anchors follow the cut), and the runs path cuts its runs without it. So the page reads `2.3 反向传播递归` and `该¹` as the paper set them, and a block without such a join has the wire text, and the cache key, it always had; a block with one gets a new key, which is what keeps the half-translated headings already cached from being served again. (An inline listing's own spaces, each a protected element between identifiers of code, were kept tight at first — set apart, `let` came back as 设; since rules 0.10.2 the whole listing is one placeholder, §5.2's `lstinline`, and no such marker is written.)
- **A block's leading label is put back at rehydration**: of the styling that flattening loses, the one a reader meets on every page is the run-in label a block opens with — `Keywords:`, `Note.`, an italic theorem statement. When the original opens with a formatting-only element (bold, italic, small caps, `\emph`; ≤ 8 words) ending in or followed by a colon, ending in a period, or being the whole block, the first matching separator in the translation ends the label; the prefix goes into a shallow clone of the element if it is no longer than the label plus a script-dependent slack, holds no sentence terminator and carries exactly the label's own placeholders (by slot identity — the engine may reorder them). Separators are recognised in the target's own script (`。．`, the danda, `۔`, …). A **period** label additionally needs the engine's sentence boundaries as evidence (§8.6), since a body sentence ends with a period too. It under-wraps and never mis-wraps: any failed condition leaves the translation as it is; the wire text and the cache key are untouched. Measured by replaying 115 such blocks through the Edge endpoint: 46/46 colon labels right, 58 of 59 period labels wrapped, the one miss rejected by the length bound. The text node the cut lands in is split together with its wire span, or the hover highlight's offsets would be wrong. **A block wholly inside one element** is the case with nothing to find — no body follows, so there is no separator, and every word of the translation goes back inside — and there the list is wider and the length unbounded: any formatting-only element (`ltx_text`, which carries a face, a size or a colour, and the emphasis element). Measured over 13 papers, 938 of 6 855 units are such (13.7 %: 720 paragraphs, 167 picture labels, 51 reference fragments), and 218 of them were listed faces over eight words — theorems set in italics — that lost their face under the default engine until 2026-09-21. What is no formatting is untouched: a link or code filling a block went out as one placeholder and comes back as itself.
- **Unforgeability.** Validation and rehydration are correct only if every placeholder on the wire was written by us. `tags` escapes `& < >` unconditionally; `markers` doubles every `@` unconditionally — after escaping, every run of literal text holds an even number of `@`, the decoder consumes `@@` in pairs, and a lone `@` is necessarily a marker. The escaping is context-free (text node by text node, then concatenated): conditional escaping breaks at the joins, where `@` + `<math/>` becomes `@@a#` and the placeholder vanishes as a literal. Cost measured: 5 `@` in 779 160 marker-format wire characters over 12 fixtures.
- **`markers` escapes `& < >` as well**: `google-web` parses the request body as HTML, and Microsoft runs an HTML tag aligner on every request, so a bare `<` fuses into a pseudo-tag. Entities are decoded **after** tokenising, so an `&#64;abc#` in a reply is never read as a marker. Both formats' wire text is therefore valid for HTML and plain-text transport alike, and no provider needs a codec of its own.
- Whitespace inside a block is kept as it is (the thin spaces around formulas matter); the cache key normalises it, the wire text does not.
- **Plain-text round trips** (the title, OCR lines) have no tokeniser and go `escapeText` → translate → `unescapeText` (`protector/escape.ts`); the placeholder path must not call `unescapeText`, since `tokenize` already restores `@@` and a second pass would eat a literal.
- A block whose voids exceed a threshold is formula-dense: it still takes the session's format but forms a batch of its own (§8.2).

### 6.3 Validation

A translation passes when the set of void ids equals the source's exactly, each once; paired tags are matched and legally nested; and no id absent from the source appears. The expectations are derived from the request text itself (`expectationsFromText`) — after escaping, every `<x>` / `<t>` in it is necessarily a real placeholder — so the check sits right beside the cache write in the background (§9) and needs no callback across the message boundary.

Failure handling: the single block is sent again with the prompt's emphasis on keeping placeholders (`cache.bypass`, so a bad entry written before is neither read nor kept), then the block falls back to the runs path, then it is marked failed with the reason (§7.6).

**The survival rate is measured, not assumed.** `pnpm e2e:placeholders` feeds a synthetic paper — 12 sentence shapes × a placeholder at the start, middle and end, against punctuation, two adjacent, inside a number, three in one sentence, a citation, a cross-reference, paired tags, seven in one sentence — to real engines and judges by counting `math` / `.ltx_cite` / `.ltx_ref` in the translation; the page fakes an arXiv URL with `page.route` and runs the whole pipeline. Google (`tags`) and Microsoft (`markers`) × Chinese, Arabic and Japanese: 60/60 came back as they went, including the one loss shape Read Frog ever saw (`256×256`). The LLM path needs a key of one's own; the tool takes an engine name.

### 6.4 Rehydration

- A placeholder is replaced by a **clone** of the node in `slots` (`cloneNode(true)`); the clone loses every `id` (duplicate anchors) and every `data-axt-*` attribute.
- **A clone carries no behaviour**: `stripInjected` (`core/marks.ts`) also removes `on*` attributes and script-running URLs (`javascript:`, `data:text/html`) from `href` / `src` / `action`, judged after normalising by the URL standard — tabs and newlines removed anywhere, controls and spaces stripped from the front — so `java&#10;script:` cannot slip past. `data:image/…` stays. arXiv emits no such attributes today; this pins the invariant rather than fixing a fault.
- All three modes use the clone; the original node is never touched — only mode hides the original block, it does not move it.
- **Refused when the page changed under the block** (#212): the slots are references to live nodes. At fill-back time the block is serialised again and compared — the text must be the same and each slot must still be the same node in the same order — and on a mismatch `rehydrate` and the runs path throw `PlaceholderIntegrityError('stale')`; the pipeline marks the block failed with the reason, sends nothing again, and the retry serialises it afresh (§10). Nothing on arXiv trips it today (its scripts never touch the body); it turns a silent wrong fill into a visible failure.

### 6.5 The runs path

Reserved for engines with `wireFormats: []` (no placeholder survives) and for the fallback after a validation failure on the other two paths. The three free engines and the LLM services all keep placeholders, so today runs is a fallback only — implemented in full all the same:

- The block is cut into text segments at the void nodes; the text inside a paired node joins its segment (styling lost). Each segment is translated on its own and joined back in order, with clones of the voids put back in place.
- **Elements with a function are kept whole** (`FUNCTIONAL_INLINE`, `a[href]`): lost styling still reads, a lost link can no longer be clicked. Measured: 0 of 4 221 fixture blocks hold such a link (arXiv's body links are all `.ltx_ref` or `mailto`, protected already), so this is a structural guarantee for the fallback, not a fix.
- A sentence interrupted by a formula is translated in pieces — an accepted degradation. The cache key carries the render path, so translations of the two paths are never reused for each other. No sentence alignment exists on this path (§8.6).

## 7. Rendering in three modes

`src/core/renderer/` and `src/styles/`. The renderer is layered and acyclic: `attrs.ts` holds every `data-axt-*` name, every injected sub-class and the one definition of the translation boundary (`TRANSLATION_EXCLUDED_CLASSES`, `REAL_TRANSLATION`); `shell.ts` builds a block's translation container; `translation.ts` owns a block's translation node (`renderText`, `renderTable`, `setState`, `clearTranslation`); `page.ts` owns the document (`enable`, `setMode`, `applyStyle`, `restore`); the side-mode tidying modules sit above; `index.ts` is a façade listing what the rest of the extension uses, and `tests/renderer/module-graph.test.ts` fails on a cycle or on a style sheet whose `.axt-t:not(…)` lists other classes than the TypeScript definition.

### 7.1 DOM invariants

1. **The translation is the original block's next sibling**, with the original's tag name and classes plus `axt-t` (`p.ltx_p` → `p.ltx_p.axt-t`), and `data-axt-for="<blockId>"`. The classes are copied so the site's own styles apply — the title's centring, the bibliography's grid columns, every heading's size all come from `ltx_*` classes. Anything cloned into a translation (a table, a rehydrated footnote) loses its `id` and every `data-axt-*`.
2. **The original may only gain `data-axt-*` attributes** — `data-axt-id`, `data-axt-state`, `data-axt-inline`, `data-axt-partial`, `data-axt-note`, `data-axt-split`, `data-axt-fit`, `data-axt-identity`, `data-axt-dup`, and the layout marks of §7.2 (`data-axt-pairs`, `data-axt-mirrored`, `data-axt-tail`, `data-axt-panels`, `data-axt-tagged`, `data-axt-translated`, `data-axt-note-translated`, `data-axt-anchor`, `data-axt-anchors`) — and its subtree is never changed. The rule is the prefix; `restore()` strips by the prefix.
3. **Global state lives on `<html>` only**: `data-axt-on`, `data-axt-mode`, `data-axt-lang`, `data-axt-dir`, `data-axt-underline`, `data-axt-blur`, `data-axt-img-modes`. A translation carries `lang` (BCP-47, from the target) and `dir` — `lang` alone leaves an Arabic paragraph's base direction ltr, with the final punctuation, digits and Latin words on the wrong side (measured on a real page); 13 target languages are right-to-left, judged by the script subtag when the tag carries one (`ms-Arab` is rtl, `ur-Latn` is not) and by the primary subtag otherwise. Only real translations get them — the skeleton and the failure widget are in the interface language, a mirror holds the original. A translated table's `lang` / `dir` go on the cells whose content was replaced, never on the `<table>` (`dir` there would flip the column order out of line with the original above). The source atoms inside an rtl translation still run left to right: formulas, code, citations, URLs and the English original inside a margin-note copy get `direction: ltr; unicode-bidi: isolate` in the style sheet, or MathML would lay `a+b` out as `b+a` and `f(x)` would lose its parenthesis to the bidi algorithm.
4. **Restore deletes every injected node** — `.axt-t` (translations, skeletons, widgets, mirrors, split copies), `.axt-img` overlays, the highlight layer and the peek panel — **and every `data-axt-*` attribute**, and removes the injected style sheets; the DOM then equals the pre-translation DOM node by node (guarded by tests on every fixture and by e2e).

The bands of the hover highlight and the original-peek panel are the two accepted exceptions to "sibling nodes only": both hang on `<body>` outside the article, carry an injected mark, and go with restore (§7.7).

**The floating button's host (`div.axt-floating`, §4.0c) is no part of a translation**: it is on `<body>` from page load, holds nothing but a shadow root, carries no `data-axt-*`, and restore leaves it where it is — it is how the reader asks for the next translation. It is therefore in the pre-translation DOM and in the restored one alike, and rule 4 holds with it present; it is not in `INJECTED_SELECTOR`, and no rule of the extractor can match it (mounted after extraction, outside the article). `tests/e2e/floating-button.mjs` checks both: before a translation it is the only thing of ours on the page, and after a restore the paper's tree, the attributes on `<html>` and the title are what they were.

### 7.2 side (side by side)

**Pairing is structural.** A block carrying `data-axt-id` always takes the left column and the right column waits for its translation; an original a mirror follows (`data-axt-mirrored`) and a figure with a split copy (`data-axt-split`) take the left column too. The marks are written the moment a session starts (§10), so the whole page turns two-column at once and never jumps sideways as translations arrive. The two column lines are defined once, on `.ltx_document`; every other container inherits them with `grid-template-columns: subgrid` and spans both; inside a container the default is full width, a paired original takes column 1 and `.axt-t` column 2:

```css
container > *                                                      { grid-column: 1 / -1 }
container > :is([data-axt-id], [data-axt-mirrored], [data-axt-split]) { grid-column: 1 }
container > .axt-t                                                 { grid-column: 2 }
```

Headings, captions and bibliography fragments pair without a rule each; no wrapper is needed and anchor ids are untouched.

**Containers are decided by structure, not enumerated**: a pairing container is every element between a block and the translation root, minus a short explicit exclusion list (translations themselves, the inside of tables, ar5iv's own two-column grids `.ltx_enumerate` / `.ltx_description`, inline and preformatted contexts, the pair members). Enumerating class names was an open set that a reader kept finding holes in; `tests/renderer/side-layout.test.ts` snapshots, per fixture, the share of pairs that reach the translation root and what each exclusion blocks, so a new hole fails the build.

**The sheet reads marks, never `:has()`.** The container is `[data-axt-pairs]`, written by `markBlocks` on every ancestor of a block together with the block marks — from a picture outwards for a block inside one, where nothing is a pairing container (§15.6); the multi-panel figure and the tagged list item are `data-axt-panels` / `data-axt-tagged`, written once per session by `markStructure` — and again on every split copy, whose marks go with every other `data-axt-*` when it is cloned (a copy without `data-axt-panels` had its row break hidden as a single-column figure's is, and a 2 × 2 figure ran in one row: 2607.24653v2, Figure 13); the last row's original is `data-axt-tail`, kept by `markTail` after every insertion and removal of an `axt-t` sibling; a frontmatter note with a real translation is `data-axt-translated`. A `:has()` in an injected sheet makes Chrome recalculate the whole document's styles on every DOM insertion — 165 ms per hover band and per arriving translation on 2312.17141, measured 2026-09-17 — and `tests/styles/no-has.test.ts` keeps the sheets free of it; the structural queries stay in TypeScript, where they cost nothing, and the tests hold the marks equal to them on every fixture. The rules that hold the layout together:

- **The two columns are `minmax(0, 1fr)`**: with `1fr`'s `auto` floor the English column holds its longest word and the Chinese column is squeezed one-sidedly; zeroed, the columns stay equal and over-wide content overflows its own column instead.
- **The container list uses `:where()`**, so the pairing rule can override it; **the column lines are inherited, never recomputed per container**, or every indented container would halve its own width and the divider would wander; a subgrid container writes `column-gap` explicitly.
- **An exclusion may only be an element that forms no grid of its own**: excluding an ancestor does not stop its descendants from subgridding a foreign grid. Everything ar5iv itself lays out as a grid (`.ltx_enumerate`, `.ltx_item`, `.ltx_biblist`, `.ltx_bibitem`) is taken over. Multi-panel flex figures (`.ltx_flex_figure`) are the exception that is safe to exclude: a flex parent's children cannot subgrid, and the pairs inside the cells are degraded to stacking explicitly.
- **Stacked areas**: inside `.ltx_td`, `.ltx_inline-block` and `.ltx_flex_cell` there is no two-column split — they are nested inside a paragraph or only half a column wide — and no mirrors are built there. The `\resizebox` wrapper (`.ltx_inline-block.ltx_transformed_outer`) is exempt: it is a shell holding one thing, and inside a stacked shell a source table and its translation were two `inline-table`s centred in one row across the divider.
- **List markers leave the grid flow**: taken over as grid items, ar5iv's hanging, grid-placed and floated markers are all blockified onto a row of their own. They are made absolutely positioned, and the mirror marker lands in the right column's slot at `calc(50% + gap / 2)`. List indentation goes on the cell content, never on a subgrid container's own padding, which would eat the first track.
- **Figures are split in two whole**: a `figure` (or an equation group with intertext rows, `SPLIT_ROOTS`) holding a pair and loose media (an image, a formula or a picture inside no translation block) is cloned; the copy (`.axt-split`) keeps only the translations, the original hides the translations inside it, and the two rows align by construction. A figure splits **as soon as it holds a pair in any state** — a skeleton, a widget, a translation or an overlay — so the layout never jumps when the caption lands; the copy's key carries every pair's state and it is rebuilt on any change; the copy carries a live retry widget of its own for a failed pair, and its duplicated media are `aria-hidden` + `inert` (§7.4b). Table floats do not split: their table has a clone already, and "loose media" keeps an inline formula in a caption from counting. Split figures are **not scaled** — ar5iv reflows flex panels by itself, and what cannot reflow scrolls inside the column — the owner's call against breaking the type-size ratio.
- **Mirrors**: every direct child of a container that is neither paired nor holds a translation — formulas, bare figures, list numbers, author paragraphs — gets a copy inserted as an `.axt-t.axt-mirror` sibling, or the right column stays empty and the content spans both. Three gates, each measured to duplicate a whole page when missing: the root must hold a translation or a block mark to count as a container; a block, and an element still holding blocks, are not mirrored; the mirror pass runs **once per session**, after the marks are written — an arriving translation changes no mirror decision. Mirrors stay in the DOM outside side mode, hidden by a `<html>` attribute rule, so a mode switch is still one attribute. Content ar5iv floats to the page's edge (`MARGIN_ASIDE`: publication notes, footnote contents) is never mirrored — its copy would float over the right column.
- **Column fitting**: tables and display formulas cannot wrap; `fitTables` measures each against the column width and steps it down (0.95 … 0.7) with `data-axt-fit`, and what still does not fit scrolls inside its column. Both members of a table pair take the wider one's step, or their rows would not line up. The measurement is **read-only** — a table cannot be pressed below min-content, so an overflowing box's width over the current zoom is its natural width; the clone-and-measure loop it replaced was a 45-second long task on 392 formula tables. Measured tables are cached by column width plus translation node identity (every render path swaps that node).
- **Footnotes appear once, at the page's right edge**: arXiv hangs footnotes in the margin at ≥ 96rem; a translated paragraph's placeholder rebuilds a copy of the footnote, so `localizeNotes` (`notes.ts`) **moves** the footnote's translation from the original into that copy (source above, translation below, on our own `.axt-note-t` rather than ar5iv's frame, which nested gives a double rule and a flying number) and hides the original with `data-axt-note="moved"`. A footnote that can never be translated (a bare URL, a lone formula — no letters, never a block) is hidden the same way once its copy reproduces it; a registered one waits for its translation, skeleton and retry widget included; but nothing is hidden when some mode hides the copy whole (an identity copy or a split copy in stack, a mirror outside side) — a duplicate beats a note gone missing. The move is idempotent; unmoved, the old source-plus-translation look is what remains, with no content lost.
- **Notes do not size their grid row, so they are stacked by hand**: a paragraph that is a grid item contains the note's float, and one paragraph measured 1 321 px tall for 54 px of text; the note box is zero-height with `overflow: visible` in side mode (ar5iv's own device inside list items), which also cancels floats avoiding each other — so `margin-notes.ts` reads every margin note once per pass and pushes each below the previous one with `translate`, which no box's height can see. Only the copies move (the original is not ours to restyle); the immovable originals are obstacles in both directions, giving way while blocks are untranslated and taking the room back as each is translated. Leaving side mode clears the shifts.
- **The frontmatter's acknowledgement and corresponding-author notes go back into the article column, in two columns, once they have a translation**: in the 1280–1535 px band ar5iv hard-codes them at 800 px and they overflow the narrower column; at ≥ 1536 px it positions them in the gutter at a fixed rhythm computed for the original alone, and a translated one presses onto the next. Without a translation they keep the gutter as it is.
- **A grid disables margin collapsing**, so the spacing the original page gets from collapsing margins becomes a sum: the two zero-height `.ltx_pagination` markers between abstract and body are zeroed in side mode, and the last row of a container has its bottom margin cleared on both cells. Measured after: 32 px, as untranslated.
- **The top margins of a row are copied level** (`pair-margins.ts`): the site's adjacent-sibling rules (`.ltx_role_affiliation + .ltx_role_affiliation`) see a different previous sibling on each side of a pair, so the two cells' `margin-top` differ; side prep copies the original's computed top margin onto the translation's inline style, wiping last round's value before measuring, and clears on leaving side. A translation in side mode never compresses its top margin (it shares a row with the original); only stack and only apply `margin: 0.25em 0 0`.
- **Width contract.** arXiv's body is a five-column grid `1fr nav article aside 1fr`. Side mode sets all three middle tracks together, body first: each side takes what is left after the body takes its full 96rem (`--axt-side-w: clamp(14rem, (100vw − 96rem) / 2, 25rem)`, the native range of the theme's `--nav-width`), the body takes the rest up to 96rem (`--axt-article-w`), the sides are symmetric so the article stays centred, and the remainder falls into the page margins (`--axt-margin-w`). All three are closed-form functions of `100vw`; no JS measures tracks; ar5iv's `--main-width` follows the article. Measured on a 145-formula paper: at 1440 px the columns are 468 px each and 57 formulas need scaling (9 can only scroll); at ≥ 2000 px 740 px each and none. The navigation takes from the freed margins first (216–384 px on wide windows) and from the body only in the 1440–1600 px band (32 px). The right gutter's geometry — ar5iv's footnote boxes, publication notes, `thanks` notes and the author area's absolute block, all written for a 52rem article — is rewritten inside `@media (width >= 96rem)` in terms of the tokens, so the boxes occupy `[article right edge + 1rem, + side − 1rem]`. Overriding `--main-width` alone overflows sideways (the navigation track does not collapse), and zeroing the track loses the table of contents.
- **Narrow windows**: `matchMedia('(max-width: 1279px)')` — the breakpoint at which arXiv's own theme turns the navigation into a drawer — switches to stack by itself and back to side on widening; a mode the reader chose stays the preference and the automatic fallback does not overwrite it (`responsive.ts`, `createModeController`). ar5iv's own breakpoints are 46 / 52 / 96 / 109 rem, the 96rem one deciding whether footnotes pop up or sit in the margin.
- **Tidying is incremental** (`prep.ts`): the pipeline hands over the blocks whose DOM just changed with every batch, a coalescer (150 ms, at most one second of waiting) collects them into a dirty set, and each pass tidies only the dirty blocks' roots — their parent, the parents of the enclosing blocks, the enclosing figure's parent — in phase order: footnotes, figure split, mirrors (first full pass only), table fit (full when the column width changes), pair margins, then the margin-note stacking as its own task. Reads sit at the start of a pass before anything is written, the column width is read only when stale. Entering and leaving side is the tidy layer's too (`prep.side(on)`), told by the session at every change of the mode in effect: entering re-reads the column, runs one full pass and watches the root's width — a width that really changed, since scaling a table makes the root report a size change itself; leaving withdraws the queued pass, ends the watch and takes back what the passes wrote **inline** (the alignment margins, the margin-note offsets), while what they wrote as `data-axt-*` marks needs no undoing, the sheet reading those under side alone; either way the split copies' duplicated media are switched (§7.4b). A step that writes inline adds its undoing there, not in the session. Measured on 880 blocks and 392 formula tables: 1 912 ms over 31 passes before, 213 ms after; what remains is the one full mirror pass, of which 138 ms is the browser's first style computation after 359 clones. `pnpm e2e:layout` guards convergence after settling (equal pair margins, every due figure split), the mirror count across side → stack → side, prep under 600 ms, and the main-thread long-task budget (longest ≤ 400 ms, total ≤ 1.5 s). No pairing registry exists: `data-axt-id` / `data-axt-for` are the only channel.
- **The layout selectors live in the rule module** (`SIDE_LAYOUT` and its neighbours): "what structure this content has" is LaTeXML knowledge as much as "which content is translated", and `selector-boundary.test.ts` keeps `ltx_*` literals out of the renderer.
- **The site's own scripts**: arXiv's page script touches only three things — the theme / TOC / reading-mode attributes on `<html>`, the table-of-contents toggle, and a `mouseup` listener that stores the selection for "report an issue" — with no MutationObserver, no MathJax (formulas are native MathML) and no footnote script; footnote pop-ups are pure CSS and a cloned mark triggers them the same. The conflict surface measured in Phase 0 is empty, and nothing on the page moves a block's nodes after load (§6.4).
- The document's title and subtitle span both columns centred and take no part in pairing (`margin-inline: auto` once the column widens); `span.ltx_p` and the paragraphs inside tables and inline blocks stack; unpaired children of `.ltx_para` span; headings and captions stack when their parent is a whole section.

### 7.3 stack (stacked)

The translation right after the original block; no extra layout, only the translation's appearance. The default mode is `side`; stack is the automatic fallback under 1280 px and a choice of its own.

- **Short headings share the line**: a heading other than the document's title with ≤ 60 visible characters gets `data-axt-inline` on both nodes, and CSS makes both `display: inline-block` with a 0.5em gap, so "Abstract 摘要" read as one line. The document title and subtitle stay stacked (inline they shrink and stick left). The rule is not limited by mode because in side mode grid items are blockified anyway and it has no effect there.
- **Block marks are written in one go**, not sliced: side prep's mirror gates read `data-axt-id`, and marks written in slices let the first pass clone half-marked containers whole into the right column (reproduced: 36 / 23 / 87 places on three fixtures). Measured in Chromium, 979 marks take 1.2 ms and force no layout, so slicing bought nothing; only the state attribute is still sliced.
- **The visibility threshold really applies, and cannot lock out oversized blocks**: `isIntersecting` means ratio > 0, so the callback compares `intersectionRatio` itself; a block taller than the root can never reach a high ratio, so the threshold is clamped to `root height ÷ element height` and aligned down to the 5 % grid the observer is registered with (`observerThresholds`), with a 1e-6 tolerance — the observer calls back only when a registered value is crossed, and the call that crosses reports the real ratio. Both cases are guarded in `pnpm e2e:layout`; a fake observer cannot reproduce them.
- **A translation identical to its source is not shown twice**: `renderText` compares after collapsing whitespace, marks an equal one `data-axt-identity`, and stack mode hides that copy; side keeps it to hold the right column, only hides the original block.

### 7.4 only (translation only)

- A translated original block is `display: none` — not deleted, no text node replaced — by the selector `[data-axt-state="translated"]`, so a pending or failed block keeps its original visible with its skeleton or retry widget beside it. Never `display: revert`: it would undo the site's own display too.
- Bibliography entries are not exempt: translated by fragments, an entry stays readable line by line. Author names in only mode are the translated names — the mode's inherent trade-off for all content; lookup is what side and stack are for.
- **In-page anchors that point at a hidden block land on the translation** (`anchors.ts`): 3.5 % of the fixtures' in-page anchors target translation blocks, and with the target `display: none` the browser scrolls nowhere. Three listeners (click capture, `hashchange`, `popstate`) redirect an invisible target to the translation node of its block and set `location.hash` — the address bar and the back button work, and the native `hashchange` is still dispatched, unlike `pushState`; re-entry is prevented by remembering the hash we wrote. Only a real translation counts as the stand-in — a mirror, a skeleton or a widget is an empty box. When the target is visible nothing intervenes, so side and stack are untouched; restore removes the listeners.
- **Resting on a translated sentence shows its original** in place after 600 ms (§7.7).

### 7.4b Accessibility: the part that is ours

The findings an audit of the rendered page reports — skipped heading levels, no `<main>` landmark, an `<object>` without a label, tables without `<th>` — are LaTeXML's and ar5iv's: the same paper without the extension already has them, and fixing them means rewriting the original's subtree, which §7.1 forbids. What is ours:

- **A translation carries `lang` and `dir`** (§7.1); `<html lang>` cannot simply be changed, since it would label the original as Chinese too.
- **Purely decorative copies are hidden from assistive technology**: mirrors, skeletons and a split copy's duplicated media (`data-axt-dup`, side mode only — outside side the original is hidden and the copy is the one reading left) carry `aria-hidden="true"` **and `inert`**: `aria-hidden` stops screen readers, not the Tab key, and a mirrored bibliography entry carries links a keyboard user would land on while the screen reader announces nothing. All of them are nodes we insert, so the attributes do not touch §7.1. Real translations are content and are never hidden.
- **The attribution is automated**: `pnpm e2e:a11y` runs axe twice on the same paper — without the extension as the baseline, then in each of the three modes — and reports only the difference. Injected content is mapped back through `data-axt-for` to the matching element in the original block; a host element is keyed by its id or by an ancestor path whose sibling indices exclude `.axt-*`, since inserted siblings would otherwise shift every selector into a false positive. Document-level rules (`region`, `landmark-*`, `page-has-heading-one`, `bypass`) are compared by rule id: the host page has no landmark at all. `scrollable-region-focusable` is printed and not judged: since Chrome 127 a scroll container without focusable children is in sequential focus by default (six containers verified by Tab round trip), and half of them are original nodes. The baseline itself must find something, or an empty difference is an empty assertion. Measured: baseline 45 items, with the extension 56 / 544 / 399 across the modes, difference empty; a low-contrast colour forced onto `.axt-t` produced hundreds of `color-contrast` items all labelled `translation`, so the mapping does not hide our own faults.

### 7.5 Translation appearance

**The appearance is the reader's own configuration, not a set of presets we supply.** A translation style is text colour + opacity + underline (`none` / `solid` / `dotted` / `dashed` / `wavy`, thickness 1 or 2) + blur-until-hover + advanced CSS declarations; a background highlight is colour + strength. Both are editable lists (`config.appearance`, v12): the built-ins (six styles, three highlights) are ordinary members that can be changed and deleted, and "reset" restores the built-ins by id and keeps the reader's own. Borders, marker backgrounds and animated effects of the MVP's 21 ported presets are gone — the reader wants to tune one to their eyes, and 21 fixed combinations covered neither that nor the screen.

- **A style only decorates on top.** A translation copies the original's classes, so font, size, line height, alignment and grid position match by nature; the injected sheet comes after the site's and must not write `font`, `display`, `margin`, `line-height` or `width` on `.axt-t` (`presets.test.ts` guards it) — `font: inherit` once overrode the abstract heading's size and the bibliography's font. **Weight is not a setting** for the same reason: it would override the bold the site gives headings.
- **The contract**: `<html>` carries two switches, `data-axt-underline` (its value the line style, written only with a line) and `data-axt-blur`; everything else is the variables `--axt-color`, `--axt-opacity`, `--axt-deco-thickness`, `--axt-hl-color`, `--axt-hl-mix`. Two injected `<style>` elements: the static sheets (modes, presets, highlight, image), written once, and a **look sheet** holding the variables and the advanced declarations, which `applyStyle` rewrites alone (`page.ts`, `appearanceRule()` in `style-preset.ts`). Values never go onto `<html>`'s inline style: restore strips by the `data-axt-` prefix, and an inline style would survive it. A hand-typed colour passes an allow-list (`sanitizeColor`); the advanced box accepts a declaration block only — the selector is ours, and `{ } @ <` are refused — against slips, not as a security boundary.
- **Underlines are drawn explicitly onto atomic inlines**: `text-decoration` does not propagate into inline-block, inline-table or MathML boxes, and `inherit` does not work either, so one shared rule sets the line on `.axt-t` and on `.axt-t :is(math, .ltx_inline-block, svg, img)` from the `--axt-deco` variable. Measured: all 51 formulas inside translations underlined.
- **Decoration lands only on real translations**: every appearance selector is `.axt-t:not(.axt-pending, .axt-error, .axt-mirror, .axt-split)` — the same boundary as `REAL_TRANSLATION` — so a skeleton, a retry widget, a mirrored formula and a split copy's wrapper are never painted; the real translations nested inside a copy still match.
- **Immediate effect**: the content script subscribes to configuration changes and `applyStyle()` rewrites the look sheet — no translation node is touched and no request is sent (`appearance` is not a chain field, §9). Measured: computed style changes at once, translation count unchanged, new requests 0.
- **Typography is not a setting** (font size, line height, column width, spacing): the body cap is pinned from both sides by the layout suite, a smaller column makes more formulas overflow (§7.2's table), and the default paragraph spacing must equal the untranslated page pixel for pixel. Issue #47 records the request.

### 7.6 The waiting state and the failed state

- **A skeleton goes in before the request goes out**: the pending node (`.axt-t.axt-pending`, the original's tag and classes, `data-axt-for`) is inserted as soon as a block is requested, so the layout takes its shape once. A text block's translation **takes the node over** when it arrives: `renderText` cancels the animation, empties the node, strips its attributes and fills it, and the page ends up the same as without a skeleton, attribute for attribute. Replacing it was two child-list changes under the block's parent, and in arXiv's own style sheet a child coming or going costs the parent's **whole subtree** a style recalculation (its positional rules, §10) — the whole paper for the document title, whose parent is `<article>`. A table's pending node is a `div` until the clone table exists, so the clone replaces it (`clearTranslation`), as a failure widget does; a short heading's stays inline (§7.3).
- **A skeleton, not a ring**: one to three bars sized in `em` — one under 120 characters of source, two under 320, else three, the last one short — an estimate from `textContent.length`, never a measurement, since reading layout here would force a reflow mid-render. The bars carry the brand colour (arXiv red at 14 % on light, 24 % on dark). The pulse is a Web Animation between full and 45 % opacity over 1.4 s (opacity is composited; a gradient sweep repaints every block every frame), capped at **60 pulsing at once** with the rest still — Read Frog measured two thousand concurrent animations taking the main thread down — off under `prefers-reduced-motion`, handles in a WeakMap and cancelled before a node is removed, or a running animation pins a detached node in the renderer. The cap, the registry and the cancellation are Read Frog's (`skeleton.ts`); only what is drawn is ours.
- Side mode's tidying recognises **real translations only**: a pending node's height says nothing about the translation. The pairing rule still applies to it, so the original and the skeleton take one column each and nothing jumps when the translation lands. In only mode the original of a pending block stays visible.
- **Failed**: the skeleton is replaced by a widget (`.axt-t.axt-error`, `failed.ts`) in a Shadow DOM — a retry button and a "!" with the reason as its title — and the original is marked `failed` with a red line. The reason is recorded per segment by the pipeline: the provider's error kind, "the translation's placeholders do not match the source", "stale", "cancelled". Retry hands the block to the run again; the popup's "retry the N failed blocks" takes the same path. The widget's strings come through `core/strings.ts` (§4.2). Read Frog's React-per-block widget was not ported: one React root per failed block, three dependencies, and their own leak.

### 7.7 Hover highlight for sentence pairs, and the original peek

When the pointer rests on a sentence of the original or the translation, **both sentences get a background band** — the question asked dozens of times a day in a long paragraph, "which sentence of the original is this". The sentence pairing comes from the engine (§8.6); a block without a verified alignment gets **its whole pair** tinted instead — a translation and its original pair by construction (`pairAt`, by `data-axt-for` / `data-axt-id`, the nearest unit winning), and only a guessed *sentence* pairing would be worse than none. So no translated block is dead to the pointer: the `runs` path, an LLM that lost a marker, a table clone paired as a whole — all light up block against block, and the engine's boundaries refine that to sentences where they exist.

- **A flat band per line, hugging nothing.** The bands are `<div>`s in one container (`.axt-hl`) hung on `<body>`, drawn from `Range.getClientRects()` — one rectangle per line, several boxes on a line merged by vertical overlap, so a line always has one band however many boxes a sentence is made of; coordinates are relative to `documentElement`, so a margin on `<body>` shifts nothing. The CSS Custom Highlight API was measured and rejected: `::highlight()` paints only the glyphs' own boxes (gaps at every formula, rising and falling with the text) and ignores `padding`, and a fade through an inherited `@property` recomputed the whole tree every frame (p95 9.1 → 13.0 ms sweeping a passage). There is no transition: without one the feature is free (p50 8.3 ms, as with the highlight off).
- **The hit test** is `caretPositionFromPoint` (`highlightsFromPoint` is Chrome 140+, the floor is 131), one call per pointer move coalesced into `requestAnimationFrame`, then a walk up to the block and two binary searches over the registered spans; the `Range` is rebuilt only when the sentence changes. The pointer must really be on the text: the caret answers "nearest insertion point" even from the margin, so the hit counts only inside that character's own rectangle plus 4 px. A miss is held 120 ms before clearing, so the gap between paragraphs does not flash.
- **What is registered** (`sentence-map.ts`): the source side's wire spans from `serialize`, the translation side's from `rehydrate`, and the verified boundaries — three things that exist together only at the instant of rendering — in a `WeakMap` keyed by the **translation** node, so the record dies with it and `restore()` needs no sweep; the original holds only a `WeakRef`. No `data-axt-*` attribute is written: hundreds of numbers per block would bloat the document and be parsed on every move. Table cells are registered cell by cell after `renderTable`; a footnote's margin copy is registered as a pair of its own (`mirrorPair`), with node mappings from flattening both trees along their known differences; **split copies are registered when the clone is made**, while the two trees are still identical, and the visible one is taken by `checkVisibility()` since a mode switch hides rather than deletes. On a retranslation with the same text length the copy's boundaries are swapped for this version's, otherwise dropped; a round without an alignment voids the copy's own record; the split's signature includes the registration state, so "text unchanged, alignment from none to some" rebuilds the copy.
- **Boundaries an engine misplaced by a character or two are snapped** to the sentence-final punctuation (§8.6); a footnote's box is carved out of the sentence's rectangles (`rangesOf` cuts at our own nodes and at `.ltx_note_outer`), and the bands are clipped to every clipping ancestor (a wide table scrolling inside its column).
- **Reflows repaint**: the bands are absolute boxes in document coordinates, so scrolling carries them; a window resize, a browser zoom, a font swap (`document.fonts` `loadingdone`), a `ResizeObserver` on `<body>`, and a `MutationObserver` on `<body>`'s subtree (`childList`, `attributes`, `characterData`; records inside the band layer and the peek panel skipped) all drop the cache and re-measure at the pointer's position — a translation inserted above pushes the sentence down without any pointer event. A container scrolling its own content repaints its band at once; the page's own scroll waits 120 ms and asks where the pointer is once it stops. An external clear (`setMode`, `applyStyle`, `restore`) bumps an epoch, or a resting pointer would take the short circuit forever. The remaining gap — a pure CSS reflow that changes neither a node nor `<body>`'s size — would cost a measurement per frame and is accepted. Cost of the observer under a translation burst, measured 2026-09-17: 3.2 ms for 1 760 records delivered in one callback, 1.1 ms in slices of 40.
- **Cost, measured 2026-09-17** (`tests/e2e/probes/highlight-lag.mjs`, the pointer swept down a column at 125 Hz in Playwright's Chromium): the hit test 0.1–0.25 ms, script 0.04 ms per frame, pointer event to DOM update 8–13 ms at the median (the frame alignment). The lag the owner saw on long papers was not the highlight's: every band rewrite made Chrome recalculate the whole document's styles — 14 ms on 2410.00260, 141–197 ms on 2609.00080v1 and 2312.17141 — because the injected sheet used `:has()`, and Chrome answers any DOM insertion under such a sheet with a whole-tree recalculation (§7.2). With the sheets free of `:has()` a band rewrite recalculates one element, 0.1–0.2 ms. `tests/e2e/probes/insert-recalc.mjs` holds that number.
- **Known gap**: rotated table headers (`rotate(-90deg)`) stack their rectangles vertically and the merge means nothing; no fixture puts a translation block inside one.
- The colour is the appearance configuration's background highlight (`--axt-hl-color` / `--axt-hl-mix`); the switch is `config.reading.sentenceHighlight`, on by default.

**The original peek in translation-only mode** (`peek.ts`, issue #141). The hover chain runs whole under only; the source side merely lands on `display: none` nodes. So when **the other side is not rendered** (`checkVisibility()` with the visibility and opacity options — the condition, not the mode, so collapsed areas and any future hidden side count too), a panel shows that sentence's original:

- **Content is a DOM clone of the sentence**, not text: a hidden subtree still clones, and formulas, links and formatting live. Cloned segment by segment (`rangesOf` cuts at our own nodes, so a translated footnote never enters), then `stripInjected` and the footnote containers removed (they float to the page edge). Not in a Shadow DOM — MathML and `ltx_*` nodes render only with the page's own sheets — but an ordinary element on `<body>` with the mark `axt-peek`, `aria-hidden`, **`inert`** (a cloned link could otherwise be tabbed to), `pointer-events: none`. Font and colour are read from the hidden side's computed style, not from system colours: arXiv sets its font on the article container and switches its theme itself, and `Canvas` / `CanvasText` painted the panel white on black under an emulated dark scheme while the page stayed white.
- **Three placements, in order**: in the article's right margin when ≥ 18rem is free **and that stretch of margin is empty** (the panel's future rectangle is intersected with every margin note's box, since ar5iv's footnotes live exactly there); else right under the sentence's last line, as wide as the visible part of its block; else, with fewer than about ten lines below and more room above, right above the first line. **Zero measurement**: the panel's height is never read — above, it hangs from `bottom` and grows upward under `max-height`; the reads it needs (the article and block rectangles, the first and last visible band) sit in the read phase with the bands. `position: fixed`, `overflow: hidden`; a sentence taller than both sides is clipped. A bubble following the cursor was rejected: it covers the neighbouring sentences and jitters.
- **A 600 ms dwell, timed by sentence identity**: jitter inside the sentence does not reset it; with the panel open a sentence change switches at once (a tooltip's warm model); leaving the text keeps the 120 ms grace, then closes and cools; **a scroll of the page or of a container closes at once and cools**, so nothing swept while scrolling pops up. When the dwell expires it first asks whether the sentence is still current (an epoch and the controller's cache); the panel's key includes the element that was cloned. Cloning is cheap: 0.010 ms per paragraph in Chromium.
- **A block whose text changed in place is closed and waits for re-registration**: for every observer record that really moves text (`movesText`) the registered block is marked stale — whether or not a panel is open — since the registered offsets no longer describe the text; the nodes we insert ourselves never count. `<html>`'s attributes are watched too, so the site's theme switch repaints the panel's colours.
- The visible side still gets its band ("which sentence am I in"); the panel uses the body font and no colour ("what does the original say"). Known limits: the original cannot be selected and copied (the panel takes no pointer events).

## 8. Providers and the translation service

`src/providers/`. One file per engine; the details of an unpublished interface are never shared across files.

### 8.0 Requests run in the background

The providers' `fetch`, the engine chain, the queues and the cache all live in the service worker. The content script's translation traffic is messages (§4.5), and the settings page's "connect" (save, then one test translation naming the chosen service) and page translation go through the same `TranslationTransport`, so "the test passes and the translation fails" cannot happen (issue #42).

What the worker answers is a table of handlers by message type (`background/handlers.ts`), each holding the rule of its message, with what it needs of the worker passed in by `background/index.ts`. The table sits behind the one listener that knows how to answer (`answerMessages`, `shared/messages.ts`): a message without a handler passes by, a promise keeps the channel open, and its rejection settles the sender's request as a failure.

**Why, measured** (2026-09-05/06, a probe extension against two local endpoints identical except for CORS headers, and against a live arXiv page):

| Where the request runs | Endpoint with CORS headers | Endpoint without | What the server sees |
|---|---|---|---|
| background service worker | 200 | **200** | origin `chrome-extension://<id>`, no preflight |
| content script, page main world | 200 after an `OPTIONS` preflight | **`TypeError: Failed to fetch`** | the page's origin; the preflight fails |
| page on `https://arxiv.org` → any `127.0.0.1` endpoint, http or https | `Failed to fetch` | `Failed to fetch` | **nothing arrives** |

A content-side request carries the page's origin and goes through a preflight (`host_permissions` does not lift this, Chrome's behaviour since 85); and a public page cannot reach a local address at all — Chrome's local-network gate, regardless of the endpoint's scheme, so a certificate on a local Ollama is no way around it. Only the background gets through. The worker's cold start is not a cost: after 40 s idle the content → background round trip measured 77–81 ms, and a request answered after a 90 s delay came back with no keep-alive of any kind — a fetch in flight keeps the worker alive, and so does an open native-messaging port (§15.3).

After the move: the API key never enters the page's isolated world; the content bundle carries no provider or AI SDK (428 kB → 152 kB); two message round trips fewer per batch. `pnpm e2e:local-endpoint` is the direct evidence: an `http://127.0.0.1` endpoint that returns no CORS header and answers every preflight with 405 translates a whole page — 12/12 segments, the server seeing only a `chrome-extension://` origin, zero preflights, zero requests from the page — where the content-side version got 0/12 and fell back silently to Google with fluent Chinese on the page all the same. The e2e asserts that the translation carries the local endpoint's prefix, not that Chinese appeared.

```ts
/** Where a translation request runs (providers/transport.ts): one interface, two implementations */
interface TranslationTransport {
  translate(call: TranslateCall): Promise<TranslateMessageResponse>
  cancel(scope: string): Promise<number>      // withdraw the scope's queued and in-flight requests; how many
  status(): Promise<ProviderStatus>
}
```

`createLocalTransport(config, deps)` (background): `buildChain` → one `createTranslateService` per engine, sharing the local cache port and the one cancelled-scope registry → `createFallbackService`. `createMessageTransport()` (`shared/transport.ts`, content and options): every method is one runtime message; a file of its own so the content bundle gets only the proxy. **Cancellation is best effort**: `axt:cancel-scope` goes to the current chain; requests still in flight on a chain a configuration change replaced finish and are blocked on the receiving end by session id (`alive()`) — turning every in-flight batch into a failure on a settings change would show a screen of retry buttons. **A call naming an engine skips the chain** (`TranslateCall.providerId`): the settings page's test asks whether *this* endpoint works, and a free fallback answering for it would be issue #42 the other way round.

```ts
interface TranslationProvider {
  id: string                          // a built-in id ('microsoft' | 'google-web' | 'chrome-builtin') or the reader's service id (svc-…)
  kind: 'llm' | 'mt' | 'builtin'
  wireFormats: readonly WireFormat[]  // the formats it preserves, by preference; [] = runs only
  maxBatchChars: number; maxBatchItems: number
  rateLimit?: { rate: number; capacity: number }   // token bucket; the service default is 8/s, burst 20
  maxConcurrent?: number              // requests open at once; the service default is 8
  isAvailable(): Promise<boolean>     // key configured, endpoint reachable, language pack ready, target language supported
  translate(request: TranslateRequest): Promise<TranslateResult>
  reportsSentences?: boolean          // reports sentence boundaries of its own (§8.6)
  promptKey?: string                  // the prompt's identity; only an engine that reads context has one
  cacheId?: string                    // the identity the cache key uses when the id is shared (§9)
}
```

Errors are `ProviderError { kind, isolatable }` with `kind` one of `no-key`, `network`, `rate-limit`, `auth`, `bad-request`, `invalid-response`, `timeout`, `aborted`, `unknown`; `no-key` and `auth` are the permanent kinds (§4.3). The kind travels across the message boundary as data (`toErrorInfo`), and the popup turns it into a sentence.

**The free engines do not support every target language**: Microsoft accepts 106 of the 179 target codes and returns a plain-text 400 for the rest (§8.3); the check reuses `isAvailable()`, the same mechanism as the built-in engine without a language pack, and the settings page warns at selection time.

### 8.2 LLM call conventions

- AI SDK 7's `generateText` + `Output.object({ schema })` with `{ segments: { id, text }[] }`; the SDK's own `maxRetries: 0`, retries left to the ported policy (§8.3).
- **The prompt has two layers**: `prompt-library.ts` (after Read Frog: the template variables `{{targetLanguage}}` `{{input}}` `{{paperTitle}}` `{{abstract}}` `{{sectionTitle}}` `{{glossary}}`, the built-ins `default` / `precision-rewrite`, the reader's own patterns, selection by `promptId`) says *how to translate*; the **protocol block** of `prompt.ts` (JSON segments, placeholder rules, output shape) is appended after any system prompt, says *how to send and receive*, and a custom prompt cannot change it. A custom prompt missing `{{input}}`, `{{targetLanguage}}` or `{{glossary}}` gets it appended, or a template created afresh would silently ignore the glossary. `PROMPT_VERSION` (`4`) enters the cache key and is bumped whenever what is sent changes meaning.
- **The protocol block shows two placeholder examples**, an unverified trade-off: Read Frog gives none, on the argument that an example gives "emit a marker" a baseline probability; validation stops any id that does not exist, so the worst case is one wasted request. Settling it needs an A/B on a real machine with an LLM key — `pnpm e2e:placeholders` can run it.
- **Metadata goes in the user message**, delimited as `<document_metadata>` and declared untrusted: a paper's title and abstract are author-written, and a paper about prompt injection may carry instruction-like text that a system prompt would take as peer instructions. The protocol block declares segments and metadata alike as data.
- **`{{targetLanguage}}` is the language's English name**, not its code ("Simplified Mandarin Chinese"), from `config/languages.ts` (ISO 639-3, the 179 codes of Read Frog's table).
- **Paper-level context goes with every batch**: `paperContext()` extracts the title and abstract once on page load — before any translation, or a later round's translation would be counted in — truncated to 1 200 characters, merged with the batch's section title; about 300 input tokens a batch. The context enters the cache key (§9), so the same passage in another paper does not hit the old translation.
- **The glossary**: `config.glossary` (`term`, `translation`), edited as text on the settings page (one entry per line, comma or tab separated, `#` comments; a faulty line is reported, not dropped; a semicolon is never a separator, since `kernel, 核; 统计学中称核函数` is one entry). Capped at 200 entries, 120 / 200 characters per side, 6 000 in all, normalised in the migration so an over-cap table cannot invalidate the whole configuration. **Only the entries a passage uses are sent** (`createGlossaryMatcher`): each passage's cache key carries its own matches, the batch's prompt carries the batch's union in the table's order; matching runs over the wire text with placeholders removed and entities decoded token by token (`R&D`, `<UNK>`), whitespace as `\s+`, NFC on both sides, word boundaries by writing system (none between Han, kana, Thai, Khmer, Lao, Burmese or Tibetan characters). The union does not enter the cache key: batching by hits measured a 5.16-fold request count, and under batching one key never pinned one prompt anyway — the neighbours in a batch influence word choice as much. With no glossary, keys and requests are byte for byte as before. An empty table sends no field, so turning the glossary on voids nothing.
- **Thinking mode is off by default**, per endpoint after KISS's registry: OpenRouter `reasoning: { effort: 'none' }`, DeepSeek `thinking: { type: 'disabled' }`, Bailian / SiliconFlow `enable_thinking: false`, nothing for an unregistered endpoint (`thinking.ts`, through the SDK's `providerOptions`); the settings drawer has the switch.
- **Batching by how much an engine takes, not by its kind**: every provider gets a `BatchQueue`; an engine with `maxBatchItems: 1` degrades to one request per item. Batches are cut by section (a heading opens a new one) within `maxBatchChars` / `maxBatchItems` (an LLM service: 1 000 characters / 4 segments, Read Frog's defaults, plus the queue's 100 ms of collecting); a table is one batch; a formula-dense block batches alone. For engines that read no context the section title is not part of the batch key, or a free engine's batches could never cross sections.
- **One chain and one set of queues for the whole browser**: rate limits are per key, not per tab. The chain is rebuilt only when a field that changes it changes (`CHAIN_CONFIG_FIELDS`: `provider`, `services`, `prompts`, `targetLanguage`, `fallback`; a test pins that every configuration field is classified); the content script writes the configuration on every mode switch, and an indiscriminate rebuild would uproot the token buckets and the degradation records. Two papers translating at once share the throughput, a deliberate trade-off.
- **Whether a failure belongs to a segment is decided at the service, not guessed by the content side.** `ProviderError.isolatable` defaults by kind — `invalid-response`, `unknown` true (splitting smaller may locate the segment); `rate-limit`, `network`, `bad-request`, `no-key`, `auth`, `aborted`, `timeout` false — and a provider overrides when it knows more (a free engine's "the response is not JSON" is systemic). Every HTTP engine — the two web translators and the OpenAI-compatible services — turns a status into a kind through one table (`kindOfStatus`): 401 / 403 `auth`, 429 `rate-limit`, 408 / 409 and 5xx `network`, every other 4xx `bad-request`; so a wrong model name or a request shape an endpoint rejects is handed to the chain at once instead of being halved into more paid requests, and an LLM batch is too small (1 000 characters, 4 segments) for a smaller one to fit a context window the whole did not. Only an isolatable failure is halved and retried down to the single block; a systemic one is reported to the chain at once. Measured before the rule: a systemic `bad-request` on 4 segments became 7 calls; a `timeout` on 8 segments fanned out into 15 content-side calls times the queue's own retries, up to 45 requests each waiting out its own timeout.
- **One batch's failure does not condemn another's results**: a call split over several queue batches may succeed in part; the failure carries `partial` (the segments that succeeded), the run renders them first, and only the rest enters the split-or-not decision. On the chain the union is gathered by segment id across steps, the later overriding the earlier — a segment translated by the first engine does not hit the cache at the second (the key carries the provider).
- **Every request has a cap**: 20 s plus 15 ms per character, at most 120 s (a 1 000-character batch 35 s); the queue races it and aborts the fetch, and a timeout is a retryable error class. Without it one hung connection left a whole paper "in progress" for good (152 of 153 blocks translated, the last never back after 220 s).

### 8.3 Free engine conventions

Treated as things that may break at any time: a file each, an error type each, a failure that switches to the next engine on the chain and never takes the extension down (hard rule 3).

- **Two throttles**: `maxConcurrent` bounds how many requests are open at once, the token bucket how many are sent per second. Google's median response is 63 ms, and a bucket of 2/s once held it to one request every 500 ms; now `google-web` runs `maxConcurrent: 2` with a bucket of 20/s (burst 8) that only catches pathological bursts. Measured on a 213-block paper with a cold cache: 31.6 s and 65 requests before, 3.0 s and 21 requests after — 9.5× faster and a third of the requests against an unofficial endpoint. `pnpm e2e` guards both a mean of ≥ 5 segments per request and at most 2 in flight.
- **Systemic failures do not enter batch-level retries**: `BatchQueue` retries three times and falls back item by item only on a count mismatch; a free engine's "the response is not JSON" is declared non-isolatable, so a batch of 100 segments is not fired 104 times at the endpoint we most want to spare.
- **HTTP statuses tell transient from permanent** (`http-errors.ts`): 429 → `rate-limit`, 401 / 403 → `auth`, other 4xx → `bad-request` (not retried, but the chain may still succeed with another engine; 408 / 409 count as transient), 5xx and connection failures → `network`.
- **A 429 pauses the whole queue** (the ported request queue): the pause is the larger of `Retry-After` and the back-off (5 s × 2^consecutive, 10 % jitter), several 429s in one window count as one, nothing is dispatched during the pause and the task that hit it is rescheduled to its end; five consecutive windows, or eight 429s on one task, drain the queue. `no-key` / `auth` drain the queue as access denied; `aborted` / `invalid-response` are non-retryable — the metadata is attached by kind when the error is constructed, since the ported policy does not know these kinds and once retried `no-key` four times.
- **`google-web`**: 8 000 characters / 100 items a request; parses the request body as HTML, so both wire formats escape `& < >` (§6.2).
- **`microsoft`** (`edge.microsoft.com/translate/translatetext?from=en&to=…`, measured 2026-09-08/09): HTTP 200 without any key, about 290 ms a call; a cap of **50 000 characters per request in total** (not items), over which the endpoint answers 400 with a **plain-text** body; the provider sends 2 000 characters / 100 items, `maxConcurrent: 8`. Language codes are BCP-47 (`zh-Hans`, never ISO 639-3), and the endpoint's own normalisation does not always match our meaning — bare `sr` comes back in Latin script while `srp` means Cyrillic — so the provider keeps a **rewrite table** (`zh → zh-Hans`, `zh-TW → zh-Hant`, `mn → mn-Cyrl`, `sr → sr-Cyrl`) and judges support by exact membership in its public language table (138 codes, re-fetched 2026-09-17, unchanged), never by the primary subtag — and three codes whose only Microsoft form would change their script (`bos`, `uzn`, `azj`) are refused outright: **106 of our 179 targets accepted, 73 refused** (the provider's own `supportsTarget` over every code, 2026-09-17; the 107/72 of the 2026-09-09 probe predates the three script exclusions), `zlm` (Jawi) among the refused rather than silently Latin. It runs an HTML tag aligner on every request (a bare `<` fuses into a pseudo-tag), returns `&lt;` / `&gt;` as they were and translates `&amp;` as a word; sentence lengths (`sentLen`) come back natively (§8.6); the whitespace of its output is collapsed before use.
- **`microsoft` can be chosen by hand but is not a fallback** (`FREE_ENGINES` is `chrome-builtin`, `google-web`): it keeps only `markers`, and a session's format is decided by the preferred engine (§8.5), so as a fallback it could serve only a `markers` session; with it chosen, Google — which keeps both formats — joins as its fallback.

### 8.4 `chrome-builtin` conventions

Measured on Chrome 152/153 (2026-09-03/05): `Translator` exists in the page's main world, the content script's isolated world **and the service worker**, and `availability()` agrees across them; language packs download per pair; `create()` needs a user gesture while the pack is `downloadable` (`NotAllowedError` otherwise), takes about 67 s for the first download with no progress events (`availability()` stays `downloadable` throughout), about 8.6 s of local loading on a later `create()` with 0→1 progress events, and 1 ms once ready; a single sentence then translates in 10–20 ms.

- `isAvailable()` recognises **`available` only**: `downloadable` / `downloading` need a gesture the automatic chain cannot supply. The download entry is a click handler — the popup's service menu and the Chrome card on the settings page (`shared/pack.ts` tracks the wanted target, the latest query and the downloads in flight, so the two surfaces agree; a finished download announces `axt:pack-changed`). The hint during the first download is indeterminate.
- **Session creation takes no batch's signal**: the session per language pair is shared by every batch (`create()` costs seconds), and a batch's timeout aborting the shared promise would fail every other batch with `aborted`, which the chain neither retries nor falls back on. Creation has its own 60 s timeout that really aborts the load through the provider's own controller and deletes the entry, or a hung `create()` would live in the cache for good.
- **The concurrency gate is provider-level**: batches are planned against the *preferred* engine's caps and forwarded as they are on a hand-over — with Google preferred that is 100 items a call — so a semaphore shared by the provider instance admits `BUILTIN_MAX_ITEMS = 20` inferences at once across every batch, not within one call. The provider declares 4 000 characters / 20 items.
- Error mapping: `NotAllowedError` / `NotSupportedError` → `no-key` (a missing gesture or language pair; retrying is useless, the chain degrades it for the session), `AbortError` → `aborted`, the rest → `unknown`. Output is normalised for the surplus space after CJK punctuation (`。 ` → `。`).
- **A finished download rebuilds the chain**: the popup or settings page sends `axt:engine-ready`, and the background rebuilds the whole chain rather than revoking a degradation record — an engine that was unavailable when the chain was built never joined it, and with the chain resident that is the common case.
- Out of e2e's reach: in headless Chromium the pack is `downloadable` and needs a gesture and a minute. Unit tests cover every branch with an injected fake `Translator`; `pnpm e2e` guarantees the chain's behaviour when the engine is unavailable; the real path is verified by hand, and on a Chrome below 138 the card reads "unavailable" and the chain skips it (probed on 137, 2026-09-17).

### 8.5 The engine fallback chain

Hard rule 3: a failure must be recoverable and must trigger the chain. `providers/fallback.ts` is a thin layer over complete services — each step is one `createTranslateService` (its own queues, cache port and batching) and the chain only hands **the same call** to the next step on failure.

- **Services are the reader's, engines are claimed by service id**: `config.services[]` holds name, address, key and model; `getProvider` builds an OpenAI-compatible engine from the entry and uses the service id as the engine id, so status, cache key and chain need no special case. A chosen service that was deleted falls to the built-in free services, and the popup says so.
- **The chain's shape**: the chosen engine first, then the free engines not duplicating it in the order `chrome-builtin` → `google-web` (offline and unthrottled first). `buildChain` (`providers/index.ts`) drops engines whose `isAvailable()` is false — no link doomed to fail — but **keeps the first engine when unavailable**, so the popup can say "no API key" instead of switching silently.
- **One wire format per session, decided by the preferred engine**: the render path fixes a block's shape and the run reads the capabilities once at the start, so switching mid-way would give blocks two shapes. The format is the first in the preferred engine's `wireFormats`; a candidate that cannot serve it stays out of the chain with a warning (Google chosen → `tags`, the built-in joins; Microsoft chosen → `markers`, Google joins). The rule is order-independent — the earlier "intersection in iteration order" let a fallback engine drag a whole session to `markers` and strip its inline styling. A preferred engine with `wireFormats: []` takes `runs`, and then the gate steps aside entirely: runs sends plain segments and any engine may serve.
- **Two degradation durations**: `no-key` / `auth` are configuration problems and degrade the engine for the session; `network` / `timeout` / `rate-limit` / `bad-request` / `invalid-response` / `unknown` are transient — a 60 s cool-down, cleared at once by a success. The queue's own retries are exhausted before the chain is reached, so nothing stacks. `aborted` never degrades: a cancellation is not the engine's fault.
- **A session is bound to the chain it started on**: a run never switches service or language mid-way. `axt:translate-page { restart }` starts a new session over a running one without showing the original first — `renderPending` removes a block's previous translation when it is requested again, so the page follows the new settings block by block, cached ones at once; the popup uses it for every service, language and prompt change. The same path runs when the chain hands over **permanently**: the run reports the serving engine, the content script asks the background why, and restarts on the engine that took over, so a page gets one engine rather than a mix; transient hand-overs keep going and come back on their own.
- **When everything is degraded, the last step is tried anyway**: better one more honest failure, reported to the run, than a state of "no engine".
- **Visibility**: `axt:provider-status` carries the engine in use and the degradation reason; the popup polls it with the progress and shows a note (a free engine's terminology is less accurate; fix the settings and translate again), and the degradation logs one `console.warn` that e2e and troubleshooting rely on. The revision the status carries is a digest of the chain's settings (`chainRevision`), the same after a worker restart.
- **The switch**: `config.fallback.enabled`, on by default; off, the chain is the chosen engine alone, and the session stops on the first permanent error (an e2e assertion each way).
- **Cancelled scopes**: every service reads the one registry the background's session router writes; a request whose scope died — tab closed, page restored, a different session reported — is refused after its cache read, before its cache write and by the batch queue's liveness hook, and nothing it returns is rendered or cached.

### 8.6 Sentence alignment


- **What it is**: `SentenceAlignment { source: number[]; target: number[] }` — sentence lengths in **wire-text coordinates**, entry *i* of each one pair. Accepted only if it reconstructs both texts exactly (`verifyAlignment`: equal non-empty counts, positive integer lengths, sums equal to each text's length); otherwise it is dropped, the block is rendered without registration, and only the highlight is lost. Matching two finished texts by position was measured first and rejected: sentence counts agreed on 67.6 % of 37 real blocks, but on the multi-sentence blocks the highlight exists for only 8 of 20.
- **Two mechanisms, one contract**: Microsoft reports natively (`sentLen`, measured on the strings sent; complete on 60/60 blocks, 96.2 % of boundaries after sentence punctuation once whitespace was collapsed); **every other engine gets markers** — the service inserts a void `<x id="N"/>` at each cut of the source and reads the target-side lengths off where the markers landed (`sentence-markers.ts`), at the service layer once rather than in each provider. Only the `tags` path is marked: `markers` has no surviving marker, and `runs` reassembles fragments without wire offsets. A segment whose marked text would exceed the engine's cap goes unmarked. No LLM reports boundaries of its own today; they take the marker path.
- **Where the cuts are chosen**: the splitter (`core/sentences`, `sentenceCuts`) runs on the wire text after serialisation — formulas are already placeholders, so `f(x) = 0.5` cannot end a sentence — over a projection in which each placeholder becomes whitespace (or a word when it opens a sentence, or `Intl.Segmenter` reports no boundary at a run-in heading); abbreviations come from a measured table. The pipeline chooses the cuts (`pipeline/cuts.ts`, carried on the segment), not the service: it needs the block to tell an annotation from a formula, and it never cuts a reference unit, on whose journal abbreviations the splitter has no precision — a fragment (authors, title, venue) or an undivided entry is aligned **whole** instead, as a single-sentence block is, so it highlights under every engine (before 2026-09-17 it was left unaligned and lit only under Microsoft's own boundaries; the owner's report).
- **The cuts enter the cache key** (`CacheIdentity.cuts`): two blocks can share a wire text with different slot semantics and different cuts, and without them in the key the second would hit the first's entry, mismatched alignment included. `CACHE_KEY_VERSION` went 5 → 6 with the markers, since the request sent changed.
- **One verification at the service, on both paths**: against the unmarked source and the returned text, and again on a cache hit — an old record may carry an alignment that no longer describes the gate.
- **A boundary off by a character or two is snapped** to the sentence-final punctuation (`snapAlignment`, after verification, so the result is exact by construction): a boundary already after punctuation stays; one with no punctuation within three characters stays (author lists); one that would leave a sentence with only placeholders stays; the punctuation must sit directly before the candidate, must not be an abbreviation's period or a decimal point, and the whole terminal run (`。”`, `……`) is crossed, straight quotes excepted; candidates are validated as a whole, ties leave the side in place, and the snap is idempotent (483 alignments replayed twice, identical). Measured over 3 532 boundaries: 2 moved, 2 fixed, 0 broken.
- **Coverage** follows the mechanism: Microsoft aligns every block it translates, references included; every other engine only on the `tags` path minus the excluded blocks; nothing on `runs`. The popup and settings say nothing about it.
- Not done, on purpose: a second aligner that guesses, boundaries from an LLM's output schema. A block without an alignment is paired whole (§7.7).

## 9. Cache and configuration

### The translation cache

IndexedDB through **Dexie** (`src/cache/store.ts`, ported from FluentRead and reshaped), held by the background alone; the content side never touches it (§8.0). Disposable by decision: clearing it costs a re-translation and nothing else, so a schema change may drop it.

- **The key** (`cache/key.ts`) is `sha256` over `CACHE_KEY_VERSION (6) | providerId | model | PROMPT_VERSION | promptKey | context | RULES_VERSION | target | renderPath | normalizedText | cuts` — every input that changes a translation, and the tests guard each distinction. `providerId` is `provider.cacheId ?? provider.id`: `openai-compat` is the same id for every endpoint, so a service declares `openai-compat:<origin><path>` (the path included — two gateway routes under one domain may be different models; never the key, hard rule 5), with `|thinking=on` or `|thinking=off` appended wherever the endpoint has an adapter that sends the switch (§8.2) — a reasoning model's translation is another output. Both states are named: before the switch entered the identity, on and off shared the unmarked one, and naming both retires those entries for this provider alone rather than bumping `CACHE_KEY_VERSION` for every engine. An endpoint that is sent nothing either way has one request and no suffix. `renderPath` shares its names with `WireFormat` plus `runs`; the same source text has the same wire text on all three, and only this field tells them apart. `normalizedText` is NFC, whitespace collapsed, trimmed — for the key only; the text sent is untouched. The version history: 3 when `renderPath` entered, 4 on its rename, 5 when serialisation began collapsing whitespace, 6 when the sentence markers changed the request (§8.6).
- **The value**: `{ translation, alignment?, paper, createdAt, lastAccessedAt, expiresAt, byteSize }`, `paper` being the arXiv id. TTL 30 days; caps of 20 000 entries and 50 MB, 256 KB per entry; an in-memory hot layer of 256 entries. The OCR results share the store under `OCR_KEY_VERSION | imageHash | helper version` (§15.2).
- **Eviction does not scan the store**: count and bytes are kept incrementally (a `byteSize` index, initialised by reading index keys alone), and only when a cap is really exceeded are the oldest entries fetched by `lastAccessedAt` in batches. The original summed every record on every `set`; measured with fake-indexeddb, 5.5 ms per set at 2 000 entries and growing, against a steady 0.11 ms after.
- **A read has a budget**: the service waits at most 2 s (`CACHE_READ_BUDGET_MS`) for a cache answer, and a timeout or a count that does not match the request is treated as all misses — one extra request beats a whole page stuck on a hung read. Measured hit round trip: tens of milliseconds. Every hit writes its access time back in its own transaction (for the LRU to be right); measured 2026-09-17 under fake-indexeddb, `getMany` of 880 keys takes 1.9 s while a batch of fresh writes costs 0.11 ms each — the service reads per request, so a screen costs tens of milliseconds; coalescing the access-time writes is a recorded candidate, not a change.
- **Bad translations never enter**: only translations that passed the placeholder check are written (§6.3), the single-block re-send carries `cache.bypass`, and nothing is written for a cancelled scope (the registry is checked once more before the write).
- **Management is a global clear on the settings page** (`axt:cache-stats`, `axt:cache-clear`): the count and size shown, expired entries removed before counting (`cleanup()`'s only runtime call, whose failure is thrown rather than reported as success), and a failure is reported as a failure — never as "the cache is empty". No per-paper clear: the key already carries engine, model, prompt and glossary, so a changed setting misses the old entry by itself.

### The configuration

WXT storage under `local:config`, a zod schema with `version` (`CONFIG_VERSION = 16`) and a chain of migration functions (`config/storage.ts`; the pattern of Read Frog's storage and migrations).

- **The shape**: `provider` (a built-in id or a service id), `services[]` (name, address, key, model, thinking; at most 20), `targetLanguage` (ISO 639-3), `mode`, `prompts`, `glossary`, `appearance` (the two lists of §7.5), `fallback.enabled`, `preload` (margin, threshold), `reading.sentenceHighlight`, `image` (enabled, modes), `uiLanguage`. `DEFAULT_CONFIG` for a first install: Microsoft, side mode, fallback on, every image mode on, the interface language following the browser.
- **A new reader's target language follows the browser, chosen once** (`config/first-target.ts`; the maintainer, 2026-09-20). It used to be Simplified Chinese for everyone. At install — `runtime.onInstalled` with `install`, never an update — the background takes **the first of the browser's preferred languages (`navigator.languages`) that is not English**, then the interface's language if that is not English either, then Simplified Chinese as before; a tag the language table cannot place is passed over (`languageOfTag`, the lookup of `fromBcp47` without its fallback), and Traditional Chinese is told from Simplified by script or region. Not the interface's language first: many who read papers run an English system with their own language second, and a paper is in English already, so English is never the target wanted. The choice is **written into the configuration, and only while nothing is stored** (`chooseFirstTarget`, value and version marker in one write): from then on it is the reader's setting, on the popup's first screen and one click from changed. Not an `auto` resolved at every read — the target enters the cache key and the chain, and a reader reordering the browser's languages would find the cache gone and the page in another language; it would also take a schema change and a migration for a decision made once. Neither reference project chooses it: Read Frog (`3b6b98d`) and FluentRead (`536a819`) both default to Simplified Chinese and read the browser's language for the interface only.
- **One mechanism**: the stored shape changes only through `CONFIG_VERSION` and a migration; no schema carries a `.default()`, so the number says exactly which fields a stored value holds, and the downgrade guard (`version > CONFIG_VERSION` → an older build reports `tooNew`) always fires. Adding a field: bump, a migration that writes the value every reader had in effect, a test with the previous version's fixture, `DEFAULT_CONFIG`. A migration that transforms values (BCP-47 → ISO 639-3 at v4; the single endpoint → `services[]` and `style` → `appearance` at v12, a full mapping with nothing falling to a default; `reading` written at v14; `preload.margin` admitting `all` and a value below one screen becoming one screen at v15) is why the number cannot be replaced by defaults. v10 changed nothing but the number, so that an older build meeting a stored `microsoft` reports the version instead of resetting the reader.
- **A fallback to the defaults is visible**: when validation fails or the version is newer than the build, `getConfig()` records why (`configFallbackReason()`), and the settings page says at the top that the key and the engine choice are not in effect (S-O-02). Triggered for real once: a v7 configuration under a v6 build, WXT refusing the downgrade, the key silently ignored for a day.
- **A stored value this build cannot read is never written over.** Every writer — the popup, the settings page, the page session saving a mode — reads, patches and writes, and on a fallback what it read is `DEFAULT_CONFIG`: one mode switch would replace the reader's services and API keys with the defaults (reproduced 2026-09-17, both causes). A newer build's configuration is valid for that build, and a broken one may be recoverable, so `setConfig` — the one gate every write passes — refuses with `ConfigUnreadableError` while the stored value does not parse. The way out is the reader's: the notice carries a two-click reset (`resetConfig`), which writes the defaults and WXT's version marker **in one storage write**, as WXT's own migration does — `setValue` writes the marker only for an empty item, and a vN value left beside a v(N+1) marker would skip the real upgrade's migration; two writes cut short between them would leave the opposite pair, which the newer build would migrate a second time. Until then the settings page shows the notice and "Data" only — the other sections would show the defaults as if they were the reader's — and the popup answers a change with a sentence (S-P-90). A mode chosen on a translated page holds for that page, unsaved; on an untranslated page nothing changes. A reset storage refuses leaves the notice up and says so. A stored version older than the build — a migration step that threw, which WXT leaves unwritten — is reported as `upgradeFailed`, not as a broken field: a later build that fixes the step may still read it, and the notice says a reset replaces it. The refusal's `name` crosses the message boundary with the failure reply (§4.5), so the popup words it the same whether its own write or the page's was refused.
- **Chain fields and volatile fields** (`config/revision.ts`): `provider`, `services`, `prompts`, `targetLanguage`, `fallback` rebuild the chain when they change; `mode`, `glossary`, `appearance`, `preload`, `image`, `reading`, `uiLanguage` do not — the content script writes `mode` on every switch, and a rebuild would uproot the queues. A test pins that the two lists together cover every field. A setting changed in the popup shows in the settings page and on the open papers without a message: everyone follows the store (`watchConfig`).
- **The surface configuration** (`shared/surface-config.ts`, bound to React by `ui/use-surface-config.ts`): what the popup and the settings page each need of the configuration, once — it was written out in both data layers until 2026-09-19, and the copies had begun to differ. One published state (the configuration with its chain digest, the fallback's reason, a refused reset, the language pack) and three rules, each a defect once: **every write is a patch on what storage holds now, and the writes run one after another** (a snapshot is stale as soon as the page writes its mode; two controls changed before the first write landed both read the same snapshot); **a change saved elsewhere is re-read on that same chain**, not taken from the event, which carries no order — and the first read queues there too; **a stored interface language that resolves to another pack than the one painted takes a reload**, which waits for what the surface says holds it (the settings page's drafts) and then for the surface's own queued writes. A write the store refuses (above) is published as what is in effect and why, then rejected: the settings page has a notice for it and resolves, the popup reports it. The pack lookup (`shared/pack.ts`) is wired here because the committed configuration owns the wanted target. **Known limit**: the serialisation is per surface — the popup, the settings page and the page session each read, patch and write from their own context, and nothing orders a write in one against a write in another. One writer in the background would (as the floating button's state has, §4.0c), at the price of turning every patch, a function of the latest value, into a named operation that can cross a message; left until a lost write is seen. The page session keeps its own chain for the mode (§4.3) behind its injected `config` dependency.
- The API key is stored locally and appears in no cache key, log, fixture or diagnostics line (hard rule 5, §4.6).

## 10. Scheduling

**Translate what is seen** — Read Frog's loading model, ported as it is (`scheduler/lazy.ts`, `pipeline/run.ts`): only the blocks in the viewport and within the preload distance below it are requested; a block never scrolled to sends no request and takes no resources. There is no separate "translate the whole paper" queue: the preload range's last stop, **whole paper** (`preload.margin: 'all'`, v15), hands every block to the run as it starts, and §8.2's batching and caps pace the requests as for any other stop. Chosen while a paper is open it applies at once — the session hands everything still waiting to both runs (`release()`); any other change of the range applies from the next session, since a running observer's distance cannot be moved and what was requested cannot be taken back.

- **A session's start reads, then writes, in one synchronous go** (`startTranslation`): the block marks (`data-axt-id`, in one go — §7.3), then **where every block is** (`ledger.measure()` → `readViewport`: each block's anchor and the anchors on the first screen), and only then the page's state (`enable`), the structural marks, every block's state attribute, and — the scheduler started from that reading — the first screen's skeletons and requests. Nothing of the start is left for a later task, so a restore cannot come in between. The order is the point: `enable` changes custom properties on `<html>`, which restyles every element of the paper, and a geometry read behind it made the browser recalculate and lay out the whole paper in the middle of the script, the first screen's requests waiting behind it (until 2026-09-19 the state attributes were written in slices and the scheduler started after the last, which is what put its read there); the skeletons written after that read then cost the frame a second whole-paper recalculation, and the translations replacing them a third (the next item). Measured on 2312.17141 (32 000 elements, side mode, the first screen from the cache; `tests/e2e/probes/toggle-timeline.mjs`): the first request for the paper's blocks reaches the background **10 ms** after the start instead of **230 ms** — on a first visit the text is that much nearer — the first skeleton is shown by 200 ms instead of 290, the first translated text by 230 ms instead of 360, and the start's long tasks add up to 500 ms instead of 640; on 2401.00418 (29 000 elements) 10 ms instead of 165, 160 instead of 210, 180 instead of 265; on 2410.00260 (2 800 elements) 10 ms instead of 45. What stays is the browser's own: one style recalculation and one layout of the whole paper for the new mode (180 ms on the first), and the mirrors' pass after it. The first screen is the one the reader was looking at when they asked; what the new layout brings into range the observer reports by itself, right after the first layout.
- **A child coming or going costs its parent's whole subtree a style recalculation on arXiv** — not by our style sheet (which holds no `:has()`, §7.2) but by the page's own: `ar5iv.css` has positional rules (`.ltx_para:first-of-type`, `:nth-of-type`, `:nth-child` inside `:has()`), Chrome keeps one invalidation set for all positional rules, and that set invalidates every descendant of the parent a child was inserted into (traced with `devtools.timeline.invalidationTracking`: `allDescendantsMightBeInvalid` on `<article>`, on the section, on the abstract). Under `<article>` that is the whole paper — 50 ms on 2312.17141 — and the document title's translation is inserted there. Hence the skeleton's node is taken over rather than replaced (§7.6): with the first screen's skeletons written in the start's own task and its translations filling them, the recalculation after the first frame covers 166 elements instead of 32 000 twice.
- Defaults: `rootMargin` **1 000 px**, `threshold` **0** (`DEFAULT_PRELOAD`), exposed on the settings page as steps ("one screen … three screens, whole paper", "just exposed … fully exposed"); the half-screen stop was dropped on 2026-09-17 and a stored value below one screen migrates to one screen. Seeding uses the same threshold as the observer — intersecting height over element height — so a block one pixel exposed does not translate at once under a configured threshold while the same block a moment later waits.
- A block sends its request when it **first** enters the viewport plus margin and is `unobserve`d at once; blocks entering in one callback **form one batch** (cut by §8.2's caps). Footnote blocks are zero-height or collapsed in ar5iv and are anchored to their paragraph. **An anchor with no box when the viewport is read is still observed**: seeding has nothing to measure, but the observer reports the element once it has a box and intersects — measured on a live paper, the last bitmaps have no box yet at `DOMContentLoaded` in ten loads of twelve, and skipping them was the one nondeterministic image check (2026-09-17). Cost at 880 blocks, measured 2026-09-17: 0.2 ms to create, 0.1 ms for every block entering at once plus 4.1 ms to claim them all (the picked × anchors walk of `release()`), 4.2 ms over 42 screens each claimed as it comes.
- A skeleton is inserted beside the block before the request goes out (§7.6); a failure swaps in the widget; a cancellation deletes it.
- **Cancellation**: restore, a tab closing or navigating away withdraw the queued and in-flight requests by session scope (the background's router, §8.5), abort the fetches, and delete the pending nodes; a result that still returns is neither rendered nor cached, and every DOM write after an `await` asks `alive()` first.
- **Progress is a state, not a task**: translated / entered the viewport / failed, with the total for reference; "translating" while requests are in flight, settled when none are, "translating" again after a scroll. Both runs report idle through one detector (`idle-trace.ts`), each with its own trace line (`[axt] session idle: …`, `[axt] images idle: …`), which the e2e suites parse.
- **No scroll anchoring of our own and no layout reads when inserting**: Chrome's native anchoring compensates (measured: 600 px inserted above the viewport, 575 px of scroll compensated, the anchor moved 0); the JS anchoring ported early forced two full-page layouts a batch — 826 cached blocks took 16.5 s with 52 long tasks — and was removed.
- **The reader's place is kept across the relayouts the extension performs on the reader's behalf** (`core/renderer/place.ts`; the maintainer, 2026-09-20: the aim is the paragraph the reader was on, not the pixel — nobody knows which word). Starting a translation, a change of the mode in effect (the reader's, or the window crossing the breakpoint) and a restore each lay the whole paper out anew, and the browser keeps the scroll offset in pixels. Measured before (`tests/e2e/probes/reading-position.mjs`, 1440×900): the paragraph on the reader's line moved 2 000–4 600 px on every one of the five actions on 2410.00260, 1 700–7 800 px on 2401.00418 — off screen each time, up to 34 paragraphs away. Chrome's anchoring does not cover this case, which is why the bullet above stands beside this one rather than against it: it stands down for a frame in which an ancestor of its anchor changes width or margins, and under translation only its anchor is hidden. **The mechanism is one call before the writes**: `keep()` notes what the browser's own hit test finds on the reader's line — a quarter of the way down the viewport, inside the text column — and how far down that element the line falls; the layout is clean then, so nothing is forced. Inside a translated block the unit is the block, whose translation stands for it when translation only hides it; one of our own nodes is read as the original beside it; between two paragraphs, where the hit is a section, the line is tried a little lower. A one-shot `ResizeObserver` — its first notification comes after the next layout, before the paint — puts that point back where it stood with one instant scroll and is gone. No timer, no window of time, no forced layout; nothing at the top of the page; and a wheel, a touch or a key before that layout means the reader is scrolling, and nothing is corrected. **Two callers**, because there are two kinds of relayout that are ours: the session (start, restore, and the mode controller's `beforeChange`), and the tidy layer's full pass under side, where mirrors by the hundred and scaled tables land in a frame Chrome does not compensate (measured: 96 px in one pass on 2401.00418). **How it was decided**: tried from inside the page first. One correction at the action alone left that 96 px; correcting for two seconds after it needed exactly one more correction, at the full pass — so the design names the pass instead of keeping a timer. Anchoring on the nearest *translation block* failed where the reader is on something that is no block (an appendix of bare formulas: the block was 1 000 px away and the stretch between changes height from mode to mode, 750 px off), which is why the anchor is whatever is on the line. After: 0–18 px on all five actions at five positions of three papers, the heaviest included, and never painted further than that in any frame of the wait. Translations arriving above the viewport afterwards are Chrome's anchoring's, as before. `pnpm e2e:layout` holds the paragraph on screen and within 80 px across the five actions.
- **Progress events go through a coalescer with a maximum wait** (`createCoalescer(fn, { delay: 150, maxWait: 1000 })`, collecting a dirty set): a pure debounce never fired while callbacks kept arriving, and side prep ran only after the whole paper was translated.
- **A concurrency cap and a total time limit** on the ported queue (`maxConcurrent` 8, `maxTotalMs` 180 s, service defaults): the token bucket bounds rate only, and under slow responses the in-flight count was bounded by nothing but the queue length; a batch that cannot be translated within the total limit fails at the deadline and leaves the retry to the reader rather than hanging. One pair of queues per provider — request queue (bucket, concurrency, timeouts, the 429 pause) and batch queue (100 ms of collecting, halving on an isolatable count mismatch, item by item as the last resort) — with the batch key of provider, model, prompt, target, render path and, for engines that read it, the section title.
- Not ported: Read Frog's `MutationObserver` for dynamic pages (arXiv is static, and its filter would take our own insertions for page changes) and giant-paragraph splitting (our blocks include whole tables, which must stay one block).

## 15. Image translation

Sections 12–14 do not exist: this one keeps the number the code's comments cite it by.

The text in a paper's figures, recognised or read out and overlaid in place, as Safari's image translation does: a rounded label over the original text in Safari's own material (§15.2), the translation sized to the box, hover for the original. **Scope**: bitmaps `img.ltx_graphics` (macOS only, through the local helper; §15.4) and externally referenced SVG figures `object[type="image/svg+xml"]` (read from their glyphs, no helper; §15.5) are overlaid; the labels of inline TikZ pictures `svg.ltx_picture` are text in the page and are **replaced in their nodes** by the text run, under the same setting and the same gate (§15.6). No entry point for a single image: once the reader translates the page, images go through the same viewport schedule as text (§10), on the same session scope; one setting says in which modes images are translated (side / stack / only, all on by default) and the popup has the switch. Switching to a mode not selected only hides the overlays; switching back shows them; a selected mode reached with images not yet translated schedules them (`resumeRaster`). Without the helper only bitmaps go untranslated; SVG and TikZ figures work regardless.

### 15.1 Judgements

- **The helper does recognition only; translation and the overlay stay in the extension.** Apple's Translation framework needs SwiftUI on macOS 15 and an installed language pack; the extension has a whole pipeline already, and an LLM can take the caption as context. The thinner the helper, the smaller the platform-specific surface. A hosted recogniser plugs into the same seam (`OcrBackend`, §15.3) when one is built.
- **Through the existing pipeline, not line by line**: Safari's context-free lines gave "Dressed sites" → 打扮的网站 and boxed a lone **B** as 字母b. Each figure's lines go in one batch with the caption and the section as context; single letters, bare numbers and identifiers are filtered before sending.
- **SVG has two populations**: inline TikZ, formerly measured to hold no text (the 2023 mathematics papers drew formulas with it) and later found to hold whole architecture diagrams (199 word-bearing labels in the corpus); and external figures, half of all figures in a 178-paper sample, whose text is exact in their glyphs. Neither is recognised: the first is text and is translated as text (§15.6), the second is read out of its glyphs and overlaid (§15.5).
- **The overlay was written from scratch** — percentage geometry, container-query font sizes, CSS anchor positioning, no measurement — after comparing the ImageTrans extension function by function; nothing was ported and no attribution applies. Its replacement of the `<img>` src is exactly what §7.1 forbids.

### 15.2 Architecture

```
content script                              background                            axt-helper (Swift, helper/)
  fetch <img> (same origin, HTTP cache)      axt:ocr { imageHash, image, scope }     Vision VNRecognizeTextRequest
  → SHA-256 → base64 ────────────────►       OCR cache by imageHash | helper version ──► length-prefixed JSON over stdio
                                             connectNative only on a miss       ◄── { lines: [{ text, quad, conf }] }
  ◄── { lines } ─────────────────────        written back to the cache
  lines → boxes (adjacent lines merged, numbers and single letters filtered)
  → the ordinary axt:translate, plain-text path, the caption in the same batch
  → an .axt-img sibling after the <img>, labels placed by normalised coordinates
```

- **Two cache layers**: the recognition by `imageHash | helper version` (deterministic; rerun only when the helper's Vision model changes), each line's translation through the ordinary text cache — the translation of "Dynamical charge" has nothing to do with which figure it is in.
- **The overlay obeys §7.1**: a sibling `.axt-img` with `data-axt-for`, never a wrapper; it carries no `.axt-t` and the `<img>` no `data-axt-id`, or side's pairing grid would lay it into the right column, the split would delete the image as a paired original, and every appearance rule would paint it. It is the third injected mark that `isInjected` / `stripInjected`, `restore()` and the split recognise.
- **Positioned with CSS anchor positioning** (Chrome ≥ 131, the install floor, for `anchor-scope`): the image carries `data-axt-anchor` and its parent `data-axt-anchors`, both written with the overlay (`renderImage`; §7.2 — a `:has()` in the sheet would recalculate the whole document on every insertion), the image names the anchor, `.axt-img` attaches with `anchor()` / `anchor-size()`, the parent limits the scope; zero geometry reads, zero `ResizeObserver`; the split copy's clone loses every `data-axt-*`, so `splitFigures` writes the two marks again for the copy's overlays. Label font sizes are container-query units computed once from the box height and character count. Measured on six charts: overlay minus image rectangle (0.0, 0.0, 0.0, 0.0) in every mode. The `.axt-img { display: none }` baseline sits outside `@supports`, so a build without the feature shows no paragraph of labels under the image.
- **The label is Safari's material, measured off Safari's own rendering** of the Transformer's Figure 1 (1706.03762, the owner's screenshots, 2026-09-21) and matched on the same figure: what lies under the label is blurred (`backdrop-filter: blur(15px)` — the fit over five boxes on four node colours has its minimum there), then veiled by `rgb(252 250 248)` at 81 %; the letters are Safari's `#5a5a5a` darkened to `#555555` at the regular weight — the lightest grey that keeps 4.5 : 1 over the veil on the darkest figure there is (over black the veil composites to (204, 202, 201), where `#5a5a5a` had 4.2 : 1; over white 7.2 : 1); a shadow falls downward. So the node's colour tints the label — over an orange node Safari measures (244, 239, 232) and ours (245, 238, 231) — and the original's letters dissolve: the luminance spread inside a label is 0.0 in Safari's, 0.4 in ours, and was 6.8 under the white veil at 92 % it replaced, where `Feed Forward` showed behind its translation. The shadow's fall-off outward matches Safari's within 2 levels a step on every side past the first pixel. **Its cost**, measured on the heaviest page with overlays (2607.24653v2, 169 labels in 11 figures, 41 in one; three full scrolls each way at 2× in headless Chromium, i.e. software compositing): a frame time of 16.7 ms at the median, p95 and p99 alike with and without the blur, and one frame over 33 ms in 6 739 against none in 7 410.
- **No DOM nodes for waiting or failed images**: a pending overlay would be cloned by the split and stripped of its state; the overlay is inserted on success only, a failure is recorded in the image run, the popup shows the count, and the retry button covers it. A label whose translation equals the original is not drawn.
- In side mode the figure is split (§7.2): the overlay belongs to the copy and the original's is hidden; the copy's key counts the overlay, so it is rebuilt when the translations complete.
- **The image run** (`core/image/run.ts`, on the shared ledger, §4.4): targets parked behind the mode gate until a selected mode is in effect; fetch → hash → OCR through a pool of **2** (bytes, base64 and the message payload all take memory, and the helper is sequential anyway); the 6 MB cap enforced while reading the response (Content-Length first, then a streaming read cancelled at once); a permanent error stops the schedule as in the text run; an animation (`frames > 1`) is handled as done without an overlay; a new session first removes the previous round's overlays. The caption is the nearest enclosing figure's own — in a multi-panel figure the outermost would give (a)'s caption to (b). Images inside translation blocks are not targets (an image inside a block is cloned into the translation with its placeholder); the fixtures' bitmaps are all loose inside figures. Cancellation carries the session scope through `axt:ocr` and the router's `onDrop` (§8.5). The one nondeterminism `pnpm e2e:image` used to show — one image of six never entering the viewport — was the scheduler skipping an anchor that had no layout box the instant the run started (§10), fixed 2026-09-17; the idle line now names any target never requested and how many the observer still holds, so a recurrence would say where.

### 15.3 The recognition boundary: seam, permission, worker lifetime, protocol

- **One seam** (`OcrBackend`, `background/ocr-backend.ts`): `status`, `ocr`, `cancel`. The image pipeline and the OCR service read through it and never learn which backend answers; today the one implementation is the Native Messaging helper client (`background/helper.ts`), and a hosted recogniser would be a second one. A result names the build that produced it, since the OCR cache key is computed from that.
- **`nativeMessaging` is optional**: requested from the "allow" button in the popup or the settings page, on the reader's gesture; denial is a state with its own copy. **A permission granted at runtime does not reach a running worker** — `connectNative` is bound when the worker's context is created — so the status has four states: `permission-missing`, `restarting` (a fresh worker is due; an alarm wakes one after the stale one idles out, and the popup's polls and the tab-update subscription pause meanwhile so the stale worker really idles), `not-installed` (with Chrome's reason), `ready` (with the version). Existing installs keep the permission across the move from required to optional (verified on Chrome 153).
- **The port keeps the worker alive** (measured 2026-09-17, `tests/e2e/probes/keepalive.mjs`: a `connectNative` port opened inside the worker, no page open, no debugger — worker and helper alive at 75 s, past the 30 s idle line), so there is no keep-alive timer — and, for the same reason, **an idle port is dropped** after 30 s with nothing pending or queued, or one popup open would keep the worker and the helper process alive for the browser session; the next request or status probe reconnects and shakes hands afresh. When the worker is recycled the port closes, the helper sees EOF and exits, every pending request is voided by `onDisconnect`, and the next request reconnects and shakes hands again — a reconnected port never reuses the old handshake, since the version is part of the cache key. With no host registered `connectNative` does not throw: the port disconnects at once with "not found" in `lastError`, remembered for the worker's life until a `recheck`. A request that times out drops the port (the helper is a synchronous loop and the timed-out request is still in its hands).

```json
{ "v": 1, "cmd": "ocr", "id": "req-1", "image": "<base64 png/jpeg>" }
{ "v": 1, "id": "req-1", "width": 1200, "height": 800, "frames": 1,
  "lines": [ { "text": "Accuracy (%)", "quad": [[0.12,0.05],[0.32,0.05],[0.32,0.08],[0.12,0.08]], "conf": 0.98 } ] }
{ "v": 1, "cmd": "ping", "id": "…" }  →  { "v": 1, "id": "…", "ok": true, "version": "0.1.0+vision3" }
{ "v": 1, "id": "…", "error": { "code": "…", "message": "…" } }
```

- `quad` is the normalised four corners, origin top-left (Vision's origin is bottom-left; the helper flips y); four corners rather than a box because a rotated axis label's corners are not axis-aligned.
- The handshake's `version` must be non-empty: it enters the OCR cache key — program version plus the revision of Vision's model, so a system upgrade that swaps the model expires the old results by itself — and a helper reporting none does not count as installed. A request carries `v`; a helper that does not recognise it answers `unsupported-protocol`, and a mismatch at the handshake is a failed handshake (queued work rejected, the port closed, "reinstall the helper" shown). The extension and the helper are installed separately and their versions will drift.
- Chrome's cap is 1 MB per message from the helper (over it the connection is cut and everything queued lost): above 250 KB of serialised lines the helper drops lines by ascending confidence until it fits and sets `truncated: true`. The 4-byte length prefix is read in full — a pipe may short-read. This protocol is an external contract: compatible or version-negotiated, never silently changed.

### 15.4 The helper

`helper/`, a Swift package with no third-party dependency: read length-prefixed JSON from stdin, decode the image, run Vision (revision 3; the recognition core after `bytefer/macos-vision-ocr`, MIT, its notice kept), write stdout; a sequential loop, one request in flight.

- **Install**: `helper/install.sh <extension id>` builds from a checkout; the settings page and popup show the one-line remote install — `curl -fsSL …/ReadarXiv/<ref>/helper/install-remote.sh | bash -s -- <extension id> <ref>` — which downloads this repository's `helper/` at `<ref>` into `~/Library/Application Support/Readarxiv/helper`, builds it with the Xcode command-line tools (about a minute the first time) and registers the host. `<ref>` is stamped into the build (`scripts/build-ref.mjs`): the commit when the tree is clean and the commit is on a branch of this repository, else `main` — so a reader installs the helper that matches the extension. `register.sh` is the single writer of the host manifest (`io.github.srjoeee.arxivtranslate`, a union of the allowed extension ids, both Chrome's and Chromium's user-level directories). The manifest lives under **the user data directory** (`<user data dir>/NativeMessagingHosts/<name>.json`, not a fixed `Google/Chrome/…`), which is why the e2e copies it into its temporary profile. No `key` is pinned in the extension manifest: an unpacked extension's id derives from its path, and pinning would change it and lose every reader's stored configuration.
- **The install runs its course in the popup**, and installation is detected by the extension (`HelperSetup.tsx`, shared by the popup and the settings page): copy the command, run it in a terminal, nothing else — the script's last write is the host manifest, which Chrome reads at the next `connectNative`, so "I have installed it" is a question the program answers itself. Copying starts `axt:helper-await`: the background probes every 2 s for at most 3 minutes, the deadline in **session** storage (a worker recycled meanwhile resumes it; a closed browser need not wait), each round scheduled before its probe so a hung probe cannot stall the wait; on detection the existing `axt:helper-ready` broadcast lets the open papers release their waiting bitmaps, and what the reader sees is the figures beginning to translate. A miss after 3 minutes adds one line of hint and keeps the command copyable. No downloadable `.command` (Gatekeeper quarantine is worse than `curl | bash`), no separate window.
- **Timeouts**: the first recognition in a worker gets 120 s (the machine's very first Vision run prepares a model once, measured 26.6 s), 30 s after one success. Measured steady state: 55 ms a recognition in-process, 160 ms end to end through the port on a miss, 6 ms on a cache hit.
- Afterword: with the helper in place an offline `apple-translate` provider (`wireFormats: []`, macOS 26's `TranslationSession`) could be added; not planned.

### 15.5 SVG figures: the text is read out, not recognised

Externally referenced figures (`<object type="image/svg+xml">`; 880 of 1 792 figures in a 178-paper sample, 49.1 %; measured over all 316 distinct assets, 276 over HTTP and 40 that arXiv serves only to a browser) have no `<text>`: every character is an outline drawn by a `<use>` into `<defs>`, and **every glyph `<use>` carries `data-text`** — 58 028 of 58 045, the 17 exceptions being hatch-fill tiles; not one `<text>`, `<tspan>` or `<foreignObject>` in the set. So the text is **read**, with zero error (`core/svg/glyphs.ts`).

- **Read only, never write**: the overlay is built in the main document from `contentDocument`, which is reachable on every figure before any scroll (84/84) and whose `viewBox` maps linearly onto the `<object>`'s box (agreement to four decimals). §7.1 and `restore()` are untouched; there is no "restore an embedded document".
- **One pipeline with bitmaps**: `glyphs.ts` produces the same `OcrLine[]` the helper returns, and everything after — boxes, the request, the cache key, scheduling, progress — is shared; `process()` branches on `ImageTarget.kind` once.
- **Segmentation by geometry**: `transform="matrix(a,b,c,d,e,f)"` decomposes into the angle `atan2(b, a)` and the font size `hypot(a, b)` (`a` alone is not the size); glyphs are projected along the baseline and a gap over 1.5 font sizes cuts a segment; superscripts separate onto their own baselines. The decomposition reads one matrix, so **a glyph with a transformed ancestor is skipped outright** — none has one in 54 344 glyphs, though 21.1 % are nested up to four deep — better untranslated than drawn from half a transform. Spaces are glyphs themselves (7.28 % of glyphs over the corpus), so a segment's text in document order is the exact original — **except in a figure made by TeX** (pgfplots, a TikZ picture compiled on its own, matplotlib under `usetex`), which draws none: to TeX a space is glue, and its labels arrived as one glued word (`CameraRepairManagementSystemReplication`), which an engine returns unchanged and which therefore drew nothing (reported on 2607.24653v2, 2 of whose 11 figures are such). In a figure with **no space glyph at all** a space is put back wherever the air between the *outlines* of two glyphs — the file holds them, a Type 1 face as `<path id>` in the font's unit square and a TrueType one as `<g id><path transform="matrix(.001,…)">` in font units under a scale, and their reach is read from the path data with no layout — is 0.22 font sizes or more: over 269 pairs of the two figures, letters of one word stand at most 0.20 apart and word gaps at least 0.26. Origins would not do (an `m` is four `i`s wide), and a figure that draws its spaces is left as it is. **In a fixed-pitch face air says nothing** — a full stop stands in a cell as wide as an `m`'s, and read by air the listing fixture with its spaces deleted came out `self . cms`, 81 spaces where none was drawn — so there a space is a **skipped cell**: a face is fixed-pitch when every advance is a whole number of its median advance (the listing's strays 0.033 at worst over 737 advances, the 14 proportional faces measured 0.25–0.37), and all 122 of the listing's spaces come back that way with none added, the ones its syntax colouring dropped among them. Held on real metrics both ways: the TeX plot reads whole, and the DejaVu plot fixture with its space glyphs deleted reads every word as it did with them (a formula does come out spaced, `| | = 89` — mathematics is set with air around its signs — and holds nothing to translate).
- **Every segment is drawn along its own axis**: 90.3 % of glyphs are horizontal, 8.5 % at −90°, 0.1 % at +90°, and 1.16 % (673) spread over 42 other angles, most often −30° — the only explanatory labels of one reported figure were at 5° and 6°. A segment carries its length along the baseline and its thickness, both normalised by the figure's width, and the label is placed at the segment's centre and turned with `rotate(θ)`; both axes use `cqw`, the same real length in any direction (`width: X%` is a percentage of the container's width, wrong vertically when the container is not square). A residual within 1.8° is zeroed so nearly-horizontal lines still merge with the line before; 180° draws upside-down text, matching the figure.
- **Code is not translated**: §5 skips listings in the HTML, but a listing inside an SVG is a bare run of glyphs that no selector reaches, so this path recognises code itself (`core/svg/code.ts`: gutters, operators, identifiers, statement ends, braces — any one signal). An identifier counts when it is called (`PyArg_Parse(`), when the run opens by assigning it (`status_message = await response.text()`), or when it is not outnumbered by the plain words beside it (`flash_attn`, `return hash_length`); **named in a sentence it does not**, the words counted outside string literals and the comment at a line's end (`status_message = "unable to load model"` is no sentence for the four words in it) — the first rule, any underscore between word characters, left all four titles of one figure in English for an `sm_89` and a `train_gpt` (`train_gpt convergence — minitriton vs torch eager`; reported on 2607.24653v2). Its spaces are the ones that go missing: a syntax-highlighted listing drops the space between two differently coloured spans (`iflog_counting`), and restoring them would need a per-run advance estimate — skipping code means not needing it. Measured over 428 translatable runs, every exclusion in the rule set was forced by a real label (`Energy (GeV)`, `LZwindow55–270keV(oneevent)`).
- **Known gap, ligatures**: the converter writes a ligature's glyph as its first letter alone — `fl`, `fi` and `ff` all arrive as `f` (`roofine`, `fnal`, `dif` in 2607.24653v2's roofline figure; the glyph ids are subset indices that say nothing of which ligature it was). The word goes to the engine misspelt and usually survives; guessing the lost letter from the outline's width would be a recogniser in all but name, and is not done.
- **Known gap**: 32 of 316 files (10.1 %) draw their letter outlines straight into `<path>` and cannot be read; rendered and classified, 11 have no text, 10 only mathematics, 2 logos, and **9 carry real word labels** that this release leaves untranslated. They are what a bitmap-style recogniser would serve.

### 15.6 Inline TikZ pictures: the labels are text, and are translated as text

LaTeXML draws a `tikzpicture` as an inline `<svg class="ltx_picture">` with each node's label in a `<foreignObject>` as plain HTML (`.ltx_foreignobject_content`). That is ordinary text in the main document, and Safari's page translation shows what follows from it: it replaces those labels like any paragraph, and the figure keeps its face, its colours and its layout. Until rules 0.11.0 the text pipeline skipped the picture whole and the labels went the images' way — a rectangle read, a white box drawn over it — which cost the figure its node colours (a diagram that says *green is a shared expert* had its nodes washed white), let the original show through the box's 8 % of transparency, and was a detour: the owner's report on 2607.24653v2, 2026-09-21.

- **A label is a block** (`picturelabel`; the picture is a container the extractor enters, the shape of an equation group and its `\intertext` row, §5). Everything a block has, a label has: the placeholders that keep `Block n−1` its formula, the cache, the batches, the fallback chain, the viewport schedule. A label wrapped over several lines holds a `.ltx_p` of its own, and then that is the block — the five "finding" boxes of 2608.29808 are whole paragraphs drawn as pictures, and are translated as the paragraphs they are. A picture inside a paragraph that is itself a block is that block's, labels and all: the paragraph cloned it whole (`CLOSED_UNDER_OUTER_BLOCK`). The test is any emitted ancestor, a footnote or an equation group between them notwithstanding: of the 170 pictures in 14 papers, 110 lie under an emitted block and **not one across such a boundary** (Devin on #277 drew the case: a footnote holding nothing but a picture); there the labels stay as the paper has them, the side a reader sees past, and a footnote's copy is `localizeNotes`' to place, which knows nothing of labels.
- **§7.1 holds to the letter**: the translation is the label's next sibling, inside the node, in an element of the label's own tag and class — so in the label's face — and the label gains a mark and nothing else. Restore removes our nodes and the page is what it was, byte for byte (measured). No exception was needed; rewriting the label in place, the first design, would have needed one.
- **One of the two shows, in every mode** (modes.css): a node was drawn for one text, and stacked the two burst it. Stacked and translation-only show the translation; under side the split figure's original keeps its labels and the copy holds the translations. A label waiting shows no skeleton and a failed one no widget — a node has no room — and the label stands as the paper has it. A translation equal to its source (`KDA`, `MLP`: 4 of 33 labels in the measured figure) is shown all the same: hidden as it is for a stacked paragraph, with the original hidden too, the node stood empty.
- **The reader's setting for figures governs it, by the images' own two mechanisms.** The display reads the same two attributes as the overlay, `data-axt-mode` and `data-axt-img-modes`: outside the ticked modes the label shows and its translation does not. And the text run has the image run's gate (`RunOptions.admit`, the ledger's `intake` with a test): a label reached while figures are off in the mode in force is **held, unasked**, and offered again when the mode or the setting changes (`resume()`). Under side the figure's copy holds whichever member of each pair shows — the translation where figures are translated in side **and the translation is there**, the original otherwise: a label waiting or failed keeps its original in the copy, the ring and the widget not being drawn in a picture (with the original gone the node stood empty, for good after a failure; Codex on #277). The setting and every pair's state are part of the copy's key.
- **Two letters make a label, maths-marked identifiers left out** (`blockTest`, asked by the place — anything inside a picture, a wrapped label's `.ltx_p` included; Devin on #277): a label is sent on its own, not inside a sentence, and on its own `N`, `q`, `L2` and a formula are symbols — and so is an identifier set as text in math mode (`softmax`, `initMT`: of the 507 labels in the measured corpus exactly one, on 2609.00246; Codex on #163). Beside words it goes with them.
- **The label's colour and face are on the span inside it**, and come back with it: 167 of the corpus's labels are wholly inside one `ltx_text` — `lower-bounded` is red by a `--ltx-fg-color` on that span — and the markers wire flattens it. A block wholly inside one formatting element gets it back around the translation, at any length (§6.3). It matters for the place as well as the colour: ar5iv centres a label whose only child is a formula, and with the span gone a label of words and a formula stood 12 px off.
- **Inside a picture nothing is a pairing container**: the container marks are written from the picture outwards (`markBlocks`), and `isSideContainer` says the same. A label's node is ar5iv's flex box with the label at its foot; marked, side's stack rule made it a block and the label dropped 23 px (measured). With both, every label of the measured figure stands where the untouched page has it, original and copy alike, to the pixel.
- **The cost**: the extractor now walks into every picture. On 2312.17141 (5 601 elements inside pictures) and two other heavy papers the difference is inside the noise of the measurement; on 2607.24653v2, which gains 162 label blocks, extraction takes about 13 ms more (82 against 70 ms, the least of seven runs each), once per page.
- **`url(#…)` in a clone needs no renaming**: `clip-path="url(#pgfcpN)"` resolves at document level onto the original's definition, both share the coordinate system, and the original stays in the document as long as our clone does.

### 15.7 The figure viewer: a figure opened large

A figure the column shows too small to read is opened large in a dialog, zoomed and panned there, and closed back onto the page where it was (issue #276). **A viewing function, not a layout change**, by measurement: in side mode on two papers at four window widths the median figure is exactly as wide as arXiv shows it — most figures are narrower than a column already — and only figures that filled the article were narrowed, and only at laptop widths (2607.24653v2: 5 of 16 under 70 % at 1280 and 1440 px, none from 1680 px); and on a laptop a figure is shown 330–470 px wide whatever we do, too small for a four-panel plot on arXiv's own page. So the viewer works in every mode, and on a page not translated, since it touches nothing of the paper.

- **DeepWiki's interaction, observed and measured** (2026-09-21, the maintainer's reference): nothing at rest; under the pointer a control fades in at the figure's top right (150 ms); a dialog of nine tenths of the window over a page dimmed at 50 % and blurred 4 px; `+` `−` `×` at its top right; a press zooms by 1.2, the wheel by 1.06 a notch about the pointer; a drag pans; each opening is a fresh fit with a margin; Escape, the backdrop or `×` closes. Its own code uses **no zoom library** — some sixty lines over pointer and wheel events; none of nine candidate libraries' signatures is among its 32 scripts — and a React dialog. Here the dialog is the platform's `<dialog>`, which gives the top layer, the focus trap and Escape, and hands the focus back to the control on closing, as DeepWiki's does not (its focus falls to the body) — while the pointer is still on the figure: closed with the pointer elsewhere, by `×` or the backdrop, the control fades and the focus falls to the body here too. Some forty-five lines of pointer and wheel handling are ours; `@panzoom/panzoom` would take thirty of them for 10 kB, and the whole viewer is 6.7 kB in the content script.
- **Two of DeepWiki's things are left out on purpose.** Zooming in place on the page would write to the paper's own node (§7.1); opening by a click anywhere on the figure cannot work for half of arXiv's figures — a click inside an `<object>` goes to its own document — so the control is the one door, for every kind of figure alike.
- **The dialog shows a copy, and the copy is what showed on the page.** A copy, because an `<object>` moved would load again. What showed: a picture's label and its translation both lie in the picture and a style rule shows one of them by where the picture stands (§15.6), so the member that did not show is taken out of the copy and every `data-axt-*` and id goes with it — no rule decides again, and opened from a split figure's original the dialog reads in the paper's words, from its copy in the reader's. The image overlay goes along only where it showed.
- **The copy is a light child of our host, slotted into the dialog** in our shadow root: it stays in the document's tree, so arXiv's sheet still sets a picture's labels and `url(#…)` still finds the paper's definitions (§15.6), while the dialog keeps a sheet of its own. A slotted node inherits along the flat tree, from the dialog, so the copy's frame is given the inherited text properties where the figure stood — at the dialog's weight of 400 instead of arXiv's 300, `Position-pair Diagonal` ran six per cent wider than TeX measured for it and wrapped over the drawing (found by diffing the two computed styles); with them, over the nine pictures of 2607.24653v2, none of 428 labels wraps otherwise than on the page. An external SVG figure is shown as an image of its file: inside an `<object>` the pointer and the wheel would be its document's; arXiv's are self-contained, every glyph an outline in the file, which is all an SVG shown as an image may be.
- **Zoom is CSS `zoom`**: the copy keeps the figure's size on the page and is zoomed as a whole — laid out and drawn afresh at the size it is shown, and every length inside with it. Measured against the alternatives on the three heaviest figures of two papers (a TikZ diagram, a plot of 1 634 glyphs under 41 labels, a bitmap; 2× pixels, real wheel and drag input, three rounds each):
  - **Frames**: 16.7 ms at the median and p95 for every method. The only difference is on the plot under its 41 blurred labels during a fast wheel zoom: a few single dropped frames of 33 ms — width and height 5 of 247, CSS `zoom` 4, Panzoom's method (a transform's scale, no `will-change`) 0 in that round but 2 of 76 with one of 100 ms in an earlier one. The same order: every method but a compositor-only one draws the figure afresh at each step.
  - **Crispness at 3×**, against the figure drawn at the size it is shown: CSS `zoom` 100 %, Panzoom's method 97.7 % on the bitmap (the small drawing stretched). A compositor-only transform (`will-change`) drops no frame and is 77–84 % sharp; switching to it for the length of a gesture only removed those few dropped frames and blurred every gesture, so it was not adopted.
  - **The overlay's look**: grown by width and height, a label's 15 px blur stayed 15 px over letters six times as thick, and the original showed through again — the spread inside a label 2.14 at 3×, 3.69 at 6×. Under CSS `zoom` the blur, the shadow and the corners grow with it: 0.90 at 6×.
- **The dialog's ground is the page's own**: arXiv has a theme of its own, and a picture's labels are set in that theme's ink — light letters on a dialog that followed a light system would not be read.
- **A figure that takes no pointer** — side makes the media a split copy repeats `inert` (§7.4b) — is never entered by the pointer, which meets the block around it instead: the figure is found by the box that holds the pointer, the moves followed only inside such a block and only while the pointer is in it.
- **Hidden, the control is out of the tab order** (`visibility`, not only opacity). A figure gone since its control appeared — side makes a figure's copy afresh as its translations arrive — opens nothing, and the control goes.
- **The page under the dialog stays where it is**, or closing would not return the reader where they were: a modal dialog does not hold the document still of itself (measured: PageDown 860 px, End to the paper's end, a swipe on the backdrop 385 px). **A scroll lock, not a list of keys**: keys held in the dialog let ⌘↓ and ⌥↓ through, and on Chrome 131 — the manifest's floor — a press on the figure puts the focus on the body, out of the dialog's hearing, where PageDown, End, Space and the arrows all scrolled the paper (measured on 131 and 153; `overscroll-behavior: contain` on the dialog held every key on 153 and none on 131). So the lock DeepWiki's dialog sets on the body, `:root { overflow: hidden }`, as a sheet the document adopts while the dialog is open and drops when it closes — no node or attribute of the page is written — with `scrollbar-gutter: stable`: a scroll bar that takes room (Windows, or macOS set to show them) stays as a gutter, where without it the paper was laid out again 15 px wider behind the dialog. Adopting and dropping it cost no frame over 16.8 ms on 2607.24653v2 and 2312.17141, with either kind of scroll bar. The arrows pan the figure and + and − zoom it while the dialog has the focus. A figure cannot take the keyboard's focus, so a reader without a pointer cannot open the viewer yet — a known limit; inside the dialog every control is a button.
- **The wheel zooms in proportion to the distance scrolled** — e^(−0.00139 · deltaY), d3-zoom's rate: 1.15 for 100 px — not by a fixed step an event, as at first: a trackpad sends a scroll as dozens of small deltas, and at 1.06 an event one gesture of 145 px went from the fit to five times it (the same gesture now 1.22). A pinch arrives as a wheel with the control key, Chrome's delta −100 · ln of the scale (measured through the DevTools protocol's pinch), so e^(−deltaY / 100) keeps the figure to the fingers; d3-zoom's pinch rate would overshoot a doubling by 31 %.
