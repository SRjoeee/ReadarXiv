## npm packages in the built extension

The extension bundles code from npm packages under MIT, ISC and Apache-2.0. All three ask that the copyright notice and the licence text go with every copy, and the minifier drops the comments that would carry them, so every build writes them into one file of the package, `licenses/third-party.txt`, beside the project's own `LICENSE` (`scripts/third-party-notices.mjs`, wired in `wxt.config.ts`). The extension shows no page for it; the file is in the package a reader installs and in the archive attached to each release.

- **The list is the bundle's own**, taken at build time from the modules that rendered code into a chunk — 21 packages on 2026-10-29 (20 on 2026-09-21), the figure recogniser's two among them (`onnxruntime-web`, MIT; `esearch-ocr`, Apache-2.0 — used as a dependency, nothing of it ported). The recogniser's worker is a build of its own, so the plugin is given to that build too (`worker.plugins`); without it those two shipped unlisted, and `scripts/check-output.mjs` now fails a build whose notices lack them. It cannot be read off `package.json`: `pnpm licenses list --prod` named three packages that never reach the bundle and missed four development dependencies whose run-time code does (`wxt`, `@wxt-dev/browser`, `@wxt-dev/storage`, `lucide`); nor off the import graph, which holds `@webext-core/match-patterns` while not a byte of it is in the output. A dependency added later is in the next build's file with nobody remembering it.
- **Each text is the package's own**, read from `node_modules`, a `NOTICE` file included (Apache-2.0 §4(d); Dexie has one). Five of the bundled packages publish no licence file to npm (`wxt`, `@wxt-dev/browser`, `@wxt-dev/storage`, `@ai-sdk/provider-utils`, `onnxruntime-web`), six with the one only the dev build bundles (`@webext-core/match-patterns`); theirs were taken unchanged from their repositories into `licenses/`, where `licenses/README.md` records the source of each. **A bundled package with no text in either place stops the build**, naming the file to add.
- **Apache-2.0's full text goes in once**, at the end (§4(a) asks for a copy of the licence): the AI SDK's packages publish only its 552-byte notice, and `@workflow/serde` a 73-byte pointer to a file it does not ship.
- **The recogniser's models are data no package manifest names**: PP-OCRv6 tiny's detection and recognition models (`public/ocr`, PaddleOCR, Apache-2.0), the two `.onnx` files byte for byte the publisher's and the character list written out of the package's `inference.yml`. The notices name them after the packages and say which file was changed how (Apache-2.0 §4(b)); `scripts/check-output.mjs` pins their SHA-256.
- **`@cantoo/pdf-lib` is a dependency of the engine, not of the extension's bundle** (MIT, a maintained fork of pdf-lib): `package.json` names it among the run-time dependencies because the engine's layout code writes PDFs with it (`src/pdf-reader/engine/layout/`: the delta, the optional-content wrap, the removal), and that code runs where the website prepares a paper and in the lab; nothing the extension loads imports it, so it is not in `licenses/third-party.txt` (checked on the 2026-10-29 build). Bundled one day, it is in the next build's list by itself.
- **PDF.js is modified in memory by the server-side reads**, not in the extension: `src/pdf-reader/engine/layout/pdf-lite.mjs` takes the text of `pdfjs-dist`'s `pdf.worker.mjs` (Apache-2.0, Mozilla) from the host and adds two guards: one line before its image decode, so that a document that opts in keeps every image operator and decodes no pixel, and one condition on a link's overlaid text, so that a document opted in with `NO_IMAGE_PIXELS` skips the second text extraction PDF.js makes it with (one opted in with `LINK_TEXT_PIXELS`, the draw geometry's, keeps it) (Apache-2.0 §4(b): a modified copy, stated in the module's header). It ships no PDF.js text; the extension and the browser layer run the unmodified package.
- **PDF.js and its data files, bundled unmodified in the PDF reader** (`pdfjs-dist` 6.3.289, Apache-2.0, Mozilla; its notice is in `licenses/third-party.txt` through the bundle's list). Beside the library the build copies, as they are, the data files the reader needs, each with its licence next to it: the character maps (`pdf-reader/pdfjs/cmaps/`, Adobe's, BSD-3-Clause, `LICENSE`), the standard fonts (`pdf-reader/pdfjs/standard_fonts/`, Foxit's and the Liberation fonts', `LICENSE_FOXIT`, `LICENSE_LIBERATION`; Liberation is SIL OFL 1.1), and the WebAssembly decoders (`pdf-reader/pdfjs/wasm/`): OpenJPEG (BSD-2-Clause, `LICENSE_OPENJPEG`), PDFium's JBIG2 decoder (BSD-3-Clause, `LICENSE_JBIG2`), QCMS (MIT, `LICENSE_QCMS`) and PDF.js's wrappers of them (`LICENSE_PDFJS_OPENJPEG`, `LICENSE_PDFJS_JBIG2`, `LICENSE_PDFJS_QCMS`). `wxt.config.ts` copies them and `scripts/check-output.mjs` checks they are in the build.
- **The fonts the PDF reader draws translations in are not in the package.** Read arXiv's website (`readarxiv.com`) serves them, cut to the characters a page needs, with their notices (`https://readarxiv.com/licenses`); their roles and licences are the engine's role table (`src/pdf-reader/engine/rules/font-roles.mjs`). The extension downloads them as data.
- **BusyTeX and the TeX page are not part of the extension.** They are parked (`parked/tex-page/`) and shipped nowhere; the TeX page's published versions at `tex.readarxiv.org` keep their own offer of source under the AGPL.
- To read the current list: `pnpm build`, then `.output/chrome-mv3/licenses/third-party.txt`.

## Who holds the copyright, and Read arXiv's website

This repository is published under GPL-3.0-only, the extension and the PDF reader's engine alike. Its copyright holder is SRjoeee (both commit identities in its history are his), except for what this page lists as taken from others: the ported files above, which stay their authors' under GPL-3.0, and the npm packages and data under their own licences.

**The code that is the copyright holder's own is also used under other terms.** Read arXiv's website (`readarxiv.com`, the private repository `readarxiv-web`) is closed source and pins this repository's engine: its server prepares papers with it, and its browser build bundles parts of it. That is not distribution of this repository under GPL-3.0; it is the copyright holder using his own code, which a licence he gives the public does not take from him. GPL-3.0 binds those who receive the code from him, not the owner of its copyright.

**The ported files are not his to license otherwise**, so the website keeps them out of everything it distributes: the Read Frog ports it uses (the Microsoft and Google adapters, the retry policy, the language tables) run on its server alone, a build that put one into its browser bundle fails (in `readarxiv-web`, its licensing page docs/licensing/gpl-code.md and its bundle check scripts/check-bundle-licence.mjs), and they are to be replaced by code written from the specifications.

**A contribution from anyone else would change this**, since it would be its author's code under GPL-3.0 alone and the website could not bundle it. So an outside pull request is accepted only by arrangement and with its author's licence grant ([`CONTRIBUTING.md`](../CONTRIBUTING.md)); a Developer Certificate of Origin sign-off alone is not enough, as it gives nothing beyond the licence the contribution is made under.

## The borrowing boundary and the licence

The project is GPL-3.0, the licence of the three extensions it ports from, so porting is direct. GPL §5 requires notices kept and modifications marked: a ported file's header reads `// Ported from reference/<repo>/<path>@<commit> (GPL-3.0), <YYYY-MM-DD>, modified: …` — the modification statement carries its date — and the file is registered in the table above; a file rewritten beyond recognition is registered all the same. `reference/` (the snapshots) is git-ignored and read-only.

What was written from scratch, on purpose: the LaTeXML rules and the extractor (the arXiv adaptation), the placeholder engine, the renderer (all three projects change, wrap or replace the original node, which the DOM invariants of DESIGN §7.1 forbid), the image overlay (compared function by function against ImageTrans; nothing ported, ideas only). Since the rebuild (the porting policy (only what is called stays)) only ported code that is called is kept: when a ported module is touched, its unused parts go, and the header and the registry row stay for what remains.
